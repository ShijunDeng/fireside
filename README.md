# 围炉夜话 Fireside

围炉夜话是一个面向团队内部的议题共创平台：有人提出值得讨论的问题，有人接过分享责任，组织者安排场次，参与者围绕一次真实分享共同学习，并把结果沉淀下来。

规范生产域名为 `firesidechat.cn`。公开访问依赖该域名的 DNS 指向实际入口；项目文档不会把未完成的 DNS 配置描述成已经可用。

## 一次议题如何走完

```text
提出问题 ──┬─ 征集分享人 → 等待认领 → 伙伴认领 ─┐
           └─ 我来分享   → 准备中 ─────────────┤
                                                ↓
                                  协调时间地点 → 已排期
                                                ↓
                                    报名 / 宣讲 / 海报
                                                ↓
                                      沉淀收获 → 知识归档
```

这里的角色是一次协作中的责任，不是账号权限：

| 角色 | 负责什么 | 如何进入流程 |
| --- | --- | --- |
| 发起人 | 提出真问题并说明为什么值得聊 | 发起议题时填写公开署名 |
| 分享人 | 准备并完成一次分享 | 创建时选择“我来分享”，或认领别人发起的议题 |
| 组织者 | 协调时间、地点和线上入口 | 使用共享口令执行排期与维护 |
| 参与者 | 报名、到场并参与讨论 | 在已排期活动中报名 |

### 发布不是认领的同义词

创建议题时必须显式选择一条路径：

- **征集分享人（默认）**：发起人只负责提出问题，议题进入“等待认领”；之后由愿意分享的伙伴填写姓名并认领。
- **我来分享**：发起人同时承担分享责任，发布时直接进入“准备中”，无需再重复认领自己。

创建或认领成功后，系统会直接进入可选的排期下一步；关闭它不会撤销刚才的操作。排期独立于发布，是因为时间、地点和线上入口通常需要另行协调。

### 共享口令何时出现

所有人都可以浏览公开议题。共享口令只保护写操作、报名名单和真实会议入口，不是登录账号。

- “解锁协作”只建立当前标签页的 8 小时协作会话，不打开业务表单。
- “发起议题”会直接打开草稿表单；未解锁时仍可完整填写。
- 第一次点击“发布议题”只打开口令层，不会自动提交或丢失草稿。
- 解锁成功后仍需再次确认发布，避免一次解锁意外创建议题。

真实口令通过生产环境配置提供，至少 6 个 Unicode 字符；不得写入仓库、URL、命令历史或前端代码。

## 状态、动作与纠错

| 状态 | 用户现在可以做什么 | 正常下一步 | 纠错路径 |
| --- | --- | --- | --- |
| 等待认领 | 查看、编辑公开内容、认领 | 准备中 | 误建或重复议题可二次确认删除 |
| 准备中 | 完善内容、安排分享 | 已排期 | 分享人可退出认领；低成熟度误建议题可删除 |
| 已排期 | 查看活动、报名、读取受保护会议入口、生成海报 | 知识归档 | 未来活动可取消排期；已结束但未举行可标记未举行并重新排期 |
| 知识归档 | 查看原活动信息、核心收获和资料 | 长期沉淀 | 误归档可撤销，回到原活动上下文 |

后端以议题版本和原子状态转换阻止重复认领、越级排期、陈旧页面覆盖新数据，以及对成熟议题的误删除。

## 日历与同日多场策略

- 列表、月历和周历共享同一份权威排期数据。
- 同一条活动轨道不允许时间重叠，但上一场结束后可以立即开始下一场。
- 月历每天预览最多三场；更多活动通过“查看全部”进入完整当日日程，不靠缩小文字硬塞。
- 周历保留每场活动的时间和状态入口；空周可以直接跳到下一场。
- 每场未来活动都能生成 1080×1440 PNG 宣讲海报；同日多场明确标注“第 N/M 场”、时间和 Topic ID，避免转发后混淆。

## 已实现能力

- 议题增删改查、状态筛选、全文搜索和持久化排序
- 认领、退出认领、排期、取消/重新排期、归档和撤销归档
- 月历、周历、当日日程，以及跨年和同日多场展示
- 围炉报名、取消报名、只读历史名单和改期/取消影响提示
- 线上会议入口脱敏与短期协作会话保护
- 一键生成宣讲海报，支持长文本和同日第 N/M 场
- 并发版本保护、失败恢复、操作完成后的稳定焦点与跨端可访问性

详细业务规则和验收证据见[规格索引](./specs/README.md)。

## 本地开发

要求 Node.js 22。安装依赖：

```bash
npm ci
```

分别启动 API 和前端开发服务：

```bash
# 终端 1：Vite 会把 /api 代理到此端口
PORT=3000 HOST=127.0.0.1 npm run dev

# 终端 2：http://127.0.0.1:5173
npm run dev:web
```

本地未设置 `FIRESIDE_WRITE_KEY` 时不启用协作口令。默认数据库为 `data/fireside.db`，可通过 `DATABASE_PATH` 改到其他路径。

验证生产构建时可使用普通用户端口：

```bash
npm run build
PORT=8080 HOST=127.0.0.1 npm start
```

## API 概览

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/api/health` | 健康检查 |
| `GET` | `/api/access` | 查询协作保护状态 |
| `POST` | `/api/access/verify` | 验证共享口令并签发短期会话 |
| `GET` | `/api/access/session` | 校验当前短期会话 |
| `GET` | `/api/topics` | 获取议题，可按状态筛选 |
| `GET` | `/api/topics/:id` | 获取单个公开脱敏议题 |
| `POST` | `/api/topics` | 创建议题 |
| `PATCH` | `/api/topics/:id` | 编辑议题 |
| `DELETE` | `/api/topics/:id` | 删除议题 |
| `POST` | `/api/topics/reorder` | 保存全局手动顺序 |
| `POST` | `/api/topics/:id/claim` | 认领议题 |
| `POST` | `/api/topics/:id/release` | 退出认领并重新开放 |
| `POST` | `/api/topics/:id/schedule` | 安排或修改分享排期 |
| `POST` | `/api/topics/:id/unschedule` | 取消排期或标记未举行 |
| `POST` | `/api/topics/:id/archive` | 归档议题 |
| `POST` | `/api/topics/:id/unarchive` | 撤销归档 |
| `GET/POST` | `/api/topics/:id/participants` | 查看名单或报名 |
| `DELETE` | `/api/topics/:id/participants/:participantId` | 取消报名 |
| `GET` | `/api/topics/:id/meeting-access` | 获取受保护的真实会议入口 |
| `GET` | `/api/stats` | 首页统计和最近排期 |

生产环境使用版本化只读 release、非 root 服务账户、systemd socket、独立 HTTPS 代理和一致备份。首次安装、证书轮换、发布及回滚必须遵循[生产运行手册](./docs/production-operations.md)，不能从 Git 工作树直接以 root 启动。
