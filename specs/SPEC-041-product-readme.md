# SPEC-041：面向业务旅程的项目入口文档

- 状态：`Accepted`
- 创建：2026-09-02
- 优先级：P2
- 关联：SPEC-003、SPEC-004、SPEC-011、SPEC-018、SPEC-019、SPEC-037

## 1. 问题

当前根 README 能列出已有功能，但没有解释谁在什么场景执行下一步，也没有说清“征集分享人 / 我来分享”两条发布路径、共享口令的介入时机和各状态的纠错动作。普通使用者必须从功能清单反推业务流程。

同时，超过三分之二篇幅是首次主机安装、release controller、systemd、备份和 TLS 操作。产品使用者难以扫描，运维人员也缺少一个职责明确、可单独引用的运行手册。

## 2. 文档职责

- 根 `README.md` 是产品与开发入口，优先回答：系统解决什么问题、有哪些角色、一次议题如何走完、关键异常如何纠正、如何本地启动与验证。
- `docs/production-operations.md` 是生产运行手册，完整保留主机安装、证书、发布、回滚、备份和权限验收，不因 README 精简而丢失安全边界。
- 规格目录继续作为需求和验收的唯一事实来源；README 只提供稳定业务总览并链接详细规格，不复制全部验收条款。

## 3. 业务表达规则

- 明确角色是一次协作中的责任，不是账号权限：发起人提出问题，分享人认领准备，组织者协调场次，参与者报名到场。
- 明确创建时显式二选一：默认“征集分享人”进入 `OPEN`；“我来分享”原子进入 `CLAIMED`。排期不塞入创建表单，创建或认领成功后再作为可选下一步。
- 明确共享口令保护写入和敏感协作信息；未解锁仍可浏览、填写发起草稿，首次发布只打开解锁层，解锁后必须再次确认发布。
- 用用户语言表达 `等待认领 → 准备中 → 已排期 → 知识归档`，并列出退出认领、取消/重新排期、撤销归档和受限永久删除等纠错路径。
- 说明同日多场的日历与海报规则：活动不可时间重叠、可首尾相接；高密度日期进入完整当日日程；海报标明第 N/M 场。
- 不在仓库文档写入真实共享口令、令牌、证书或私钥。

## 4. 验收

1. 新读者在根 README 前半部分即可找到产品定位、角色、两条发布路径、完整生命周期、日历/海报多场策略和纠错路径。
2. “发起议题”与“解锁协作”有不同任务说明，且与 SPEC-018 和真实页面一致。
3. README 提供可复制的本地开发、生产构建和质量检查命令，命令与 `package.json`/Vite 代理一致。
4. API 总览保留；生产细节从根 README 移入单独运行手册，根 README 可直接到达该手册、规格索引和主要源码目录。
5. 生产运行手册保留原有安装、TLS、发布、回滚、备份和权限检查内容，内部规格链接有效。
6. Markdown 链接检查、`npm run check` 通过；本轮只改文档，不改变业务运行态。
