# SPEC-002：CRUD、排序与日历工作台

- 状态：`Accepted`
- 创建：2026-09-01
- 最后更新：2026-09-01
- 依赖：SPEC-001

## 1. 背景

核心平台已经支持生命周期动作，但组织者无法更正内容、删除无效议题、调整展示顺序，也无法从时间维度规划分享。此次迭代将议题广场升级为完整管理工作台。

## 2. 范围与非目标

范围：

- 议题的完整创建、读取、更新、删除。
- 持久化手动排序与常用自动排序。
- 列表、月历、周历三种视图。
- 从日历事件直接进入编辑。

非目标：

- 不实现循环日程、拖动日历事件改期、外部日历同步。
- 不实现登录、权限或删除恢复站。
- 不在本迭代引入多人实时协同协议。

## 3. 功能需求

### FR-MGMT-001 更新议题

- 任意状态的议题均可修改标题、简介、发起人与标签。
- 非 `OPEN` 议题可修改分享人。
- `SCHEDULED` 与 `ARCHIVED` 可修改时间、时长和地点。
- `SCHEDULED` 与 `ARCHIVED` 可修改独立的 http/https 会议链接；旧 room URL 按 SPEC-004 兼容读取。
- `ARCHIVED` 可修改收获摘要和资料链接。
- 更新不得绕过 SPEC-001 的状态机。
- 更新成功后必须刷新 `updated_at`。

### FR-MGMT-002 删除议题

- 原“任意议题均可删除”已由 SPEC-017 替代：只有 `OPEN / CLAIMED` 且不存在成熟业务依赖时可永久删除。
- `SCHEDULED / ARCHIVED` 必须沿生命周期先取消排期、标记未举行或撤销归档，不能用 DELETE 代替业务纠错。
- 前端必须展示包含议题标题的二次确认。
- 删除成功返回 `204 No Content`，再次读取时不可见。
- 删除不存在的议题返回 `404`。

### FR-SORT-001 自动排序

议题列表支持：

- 手动顺序（默认）
- 最新创建
- 最早创建
- 排期时间（有排期的优先）
- 状态（即将开讲、待认领、准备中、已归档）

排序参数只能使用白名单，不得直接拼接用户输入。

### FR-SORT-002 持久化手动排序

- `topics.position` 保存全局手动顺序。
- 新议题默认追加到末尾。
- 只有“全部议题 + 无搜索词 + 手动排序 + 列表视图”时允许调整全局顺序。
- 桌面支持从显式手柄拖动；整张卡片不得抢占拖动。
- 触屏与键盘用户可使用上移/下移按钮完成相同操作。
- 首项不可上移，末项不可下移。
- 保存失败时回滚原顺序并提示；成功后刷新仍保持。
- 排序变化通过 `aria-live` 宣告当前位置。

### FR-CAL-001 视图切换

- 议题广场提供列表、月历、周历切换。
- 切换不丢失状态筛选和搜索条件。
- “本周排期”导航必须进入当前周的周历，而不是只做状态筛选。

### FR-CAL-002 月历

- 从周一开始，固定显示完整的 6 周（42 天）网格。
- 支持今天、上一月、下一月导航。
- 相邻月份日期弱化；当天突出显示。
- 只有存在 `scheduledAt` 的议题进入日历。
- 每个事件展示时间和标题；点击进入编辑。
- 按 SPEC-019，单日超过 3 场时展示剩余数量，并进入有界的完整当日日程 dialog；不在日格内无限展开。

### FR-CAL-003 周历

- 从周一到周日展示当前自然周。
- 支持今天、上一周、下一周导航。
- 每个事件展示时间、标题、分享人、地点和时长；按 SPEC-019，同日超过 3 场时使用完整当日日程，避免单列无界增高。
- `SCHEDULED` 与 `ARCHIVED` 使用可辨识的不同样式。
- 无事件日期展示安静的空状态。
- 移动端允许横向滚动，不能压缩到不可读。

## 4. 数据与迁移

为 `topics` 新增：

| 字段 | 类型 | 默认值 | 用途 |
| --- | --- | --- | --- |
| `position` | INTEGER NOT NULL | `0` | 持久化手动顺序 |

迁移要求：

- 启动时检查 `PRAGMA table_info(topics)`。
- 旧数据库缺少字段时执行 `ALTER TABLE`。
- 历史数据以 `id` 初始化顺序，不丢失任何业务字段。

## 5. API 契约

### `GET /api/topics`

新增 `sort=manual|newest|oldest|schedule|status`，默认 `manual`；可与 `status` 一起使用。

### `PATCH /api/topics/:id`

接受 FR-MGMT-001 允许的可选字段，至少包含一项。返回更新后的完整议题。

### `DELETE /api/topics/:id`

允许状态成功为 `204`；不存在为 `404`；revision 陈旧为 `412`；成熟状态或异常成熟依赖为 `409 TOPIC_DELETE_STATE_CONFLICT`。完整契约见 SPEC-017。

### `POST /api/topics/reorder`

请求：`{ "orderedIds": [3, 1, 2] }`。

- ID 不得重复。
- 必须恰好包含当前全部议题，防止部分视图误覆盖全局顺序。
- 在一个 SQLite 事务中写入连续 `position`。
- 成功为 `204`。

## 6. 交互与可访问性

- 所有图标按钮都有可感知的 `aria-label`。
- 编辑和删除弹窗复用统一 dialog。
- 删除按钮与常规动作有明确的危险色区分。
- 月历、周历事件使用原生 `button`，可键盘聚焦与触发。
- 非手动场景隐藏排序操作，并显示可理解的提示。

## 8. 实现记录

### 2026-09-01 浏览器验收第 1 次

- 通过：桌面月历、周历、本周导航与手动排序持久化。
- 发现 `BUG-CRUD-001`：浏览器 `DELETE` 请求无 body 但统一附加 `Content-Type: application/json`，Fastify 将其判为 JSON 解析错误并返回 500；API inject 测试未覆盖真实 HTTP 解析层。

- API 客户端仅在存在 body 时设置 JSON Content-Type。
- E2E 移动项目使用 Chromium 移动设备配置，与 CI 安装项一致。
- 删除浏览器规格必须等待 `204`，并验证弹窗关闭和卡片消失。
