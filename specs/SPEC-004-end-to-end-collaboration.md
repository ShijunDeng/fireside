# SPEC-004：端到端议题协作与宣讲闭环

- 状态：`Implementing`
- 创建：2026-09-01
- 最后更新：2026-09-01
- 依赖：SPEC-001、SPEC-002、SPEC-003

## 1. 背景与产品目标

现有系统已经具备创建、认领、排期、归档的正向状态机，但“有接口”不等于“用户旅程完整”：发起人想自己分享仍需重复认领；误认领和取消活动只能靠删除；页面声称支持会议链接和“只听”，却没有加入会议或报名入口；流程说明和统计卡也没有全部连接到真实动作。

本规格从用户视角定义一个成熟、低门槛且可纠错的围炉协作系统：

- 一个议题既可以由发起人征集其他分享者，也可以由发起人自己分享。
- 正向流程与常见撤销路径完整，删除不再承担流程纠错。
- 参与者能够报名、取消报名并进入线上会议。
- 已排期议题能够一键生成可传播、不会泄露会议凭证的宣讲海报。
- 页面上的功能性文字、按钮和状态都与真实能力及数据口径一致。
- 公网部署保持公开可读，写操作只对持有围炉口令的协作者开放。

## 2. 产品角色与信任边界

| 角色 | 目标 | 当前身份语义 |
| --- | --- | --- |
| 发起人 | 提出值得探索的问题 | 创建时填写署名 |
| 分享人 | 接过议题并准备分享 | 认领或自荐发布时填写署名 |
| 参与者 | 报名旁听或参加活动 | 报名时填写署名 |
| 协调者 | 排期、纠错、归档 | 持有团队共享围炉口令 |
| 浏览者 | 浏览、搜索、看日历和归档 | 无需口令 |

当前版本不声称拥有可验证的个人身份。姓名是公开署名，围炉口令只区分“公开浏览者”和“可信协作者”，不伪装成发起人/分享人的细粒度权限系统。个人账号、组织隔离和审计日志属于后续产品边界。

## 3. 核心产品决策

### DEC-004-001 发布意图显式二选一

创建表单必须提供互斥选择：

1. **征集分享人（默认）**：发布后为 `OPEN`，`presenter = null`；适合“我对它好奇，希望有人来讲”。
2. **我来分享**：发布时在同一个数据库事务中写入 `presenter = proposer` 并进入 `CLAIMED`；适合发起人已有分享意愿。

不按姓名猜测意图，不把排期塞进创建表单。排期通常需要额外协调，作为下一步更清楚且便于撤销。

### DEC-004-002 线下分享不新增虚假站内状态

不新增 `LIVE` 或 `COMPLETED`。实际宣讲发生在会议室或外部会议软件：平台用报名、加入会议和海报支持活动发生；分享结束后由协调者填写收获并归档。

### DEC-004-003 所有可见承诺必须闭环

“会议链接”“可以只听”“围炉分享”“还有 N 个议题”“下一场”等文案必须连接到真实入口；如果仅是线下说明，必须清楚标注，不得伪装成站内动作。

## 4. 完整状态机与不变量

```text
发布并征集                         自荐发布
    │                                │
    ▼                                ▼
OPEN ──────────── 认领 ──────────> CLAIMED
 ▲                                  │
 └──────────── 退出认领 ────────────┘
                                    │ 排期
                                    ▼
                         CLAIMED <── SCHEDULED
                                  取消排期 │
                                           │ 分享结束并归档
                                           ▼
                         SCHEDULED <── ARCHIVED
                                  撤销误归档
```

| 状态 | 必须存在 | 必须为空 | 核心动作 |
| --- | --- | --- | --- |
| `OPEN` | proposer | presenter、排期、归档、参与名单 | 认领 |
| `CLAIMED` | proposer、presenter | 排期、归档、参与名单 | 退出认领、排期 |
| `SCHEDULED` | presenter、scheduledAt、duration、room | archivedAt | 报名/取消报名、加入会议、生成海报、改期、取消排期、归档 |
| `ARCHIVED` | 完整排期、takeaway、archivedAt | — | 查看资料与参与记录、撤销误归档 |

反向转换清理规则：

- 退出认领：清空 `presenter`，其他议题内容不变。
- 取消排期：清空 `scheduledAt`、`duration`、`room`、`meetingUrl` 并删除该议题全部报名；确认文案必须说明报名会被取消。
- 撤销归档：保留原排期与参与名单，清空 `takeaway`、`materialUrl`、`archivedAt`。
- 普通改期保留参与名单，并提示系统暂不自动通知参与者。
- 正向和反向转换全部使用 `UPDATE ... WHERE status = ?`；陈旧状态返回 `409`，前端提示后加载权威结果。
- 永久删除只允许 `OPEN / CLAIMED` 且仅用于误建或重复议题；`SCHEDULED / ARCHIVED` 必须先按上述真实生命周期纠错，完整门禁见 SPEC-017。

## 5. 功能需求

### FR-FLOW-001 发布与自荐

- `POST /api/topics` 接受可选 `presenter`；存在时必须是 1–30 字并原子创建 `CLAIMED`，否则创建 `OPEN`。
- 前端用明确选项表达意图；“我来分享”时 presenter 固定等于 proposer，不要求重复填写姓名。
- 成功反馈区分“正在征集分享人”和“已进入准备中”。

### FR-FLOW-002 退出认领

- `POST /api/topics/:id/release` 仅允许 `CLAIMED → OPEN`。
- 成功清空 presenter；不存在返回 `404`，状态已变化返回 `409`。
- 前端必须二次确认，成功后显示“已重新开放认领”。

### FR-FLOW-003 取消排期

- `POST /api/topics/:id/unschedule` 仅允许 `SCHEDULED → CLAIMED`。
- 在同一事务中删除报名并清空全部排期/会议字段。
- 前端确认框明确说明日历事件和现有报名会被移除。

### FR-FLOW-004 撤销误归档

- `POST /api/topics/:id/unarchive` 仅允许 `ARCHIVED → SCHEDULED`。
- 保留排期和报名；清空归档摘要、资料链接和归档时间。
- 前端确认后恢复为已排期状态，可重新归档。

### FR-JOIN-001 地点与会议链接

- 排期字段拆分为：`room`（必填，1–60 字地点/参与说明）和 `meetingUrl`（可选，最长 2048 字，仅 `http/https`）。
- 数据库新增可空 `meeting_url`；已有把 URL 存在 room 的数据继续兼容展示为线上会议链接，不强制改写历史业务字段。
- 列表卡片与周历为合法 URL 提供独立、可聚焦的“加入会议”链接，在新标签打开并使用 `rel="noreferrer"`。
- 周历的“编辑议题”和“加入会议”不得形成嵌套交互元素，点击加入会议不能打开编辑弹窗。
- 普通地点只显示文本；非 HTTP(S) 永不渲染为链接。

### FR-JOIN-002 报名与取消报名

- 新增 `topic_participants(id, topic_id, name, normalized_name, created_at)`；外键随议题删除级联，`UNIQUE(topic_id, normalized_name)` 防重复报名。
- 姓名去除首尾空格并以 Unicode 小写结果归一化；展示保留原始大小写。
- 只有 `SCHEDULED` 可报名；`POST /api/topics/:id/participants` 成功返回 `201`，重复姓名返回 `409`。
- `GET /api/topics/:id/participants` 仅对已解锁协作者开放；匿名列表只公开参与人数，不公开姓名。
- `DELETE /api/topics/:id/participants/:participantId` 仅在 `SCHEDULED` 可取消。
- 卡片显示参与人数，“报名参加”打开名单；同一弹窗支持报名和取消自己的署名。无身份系统时，取消动作不声称校验本人。
- 归档后名单冻结但仍可查看。

### FR-JOIN-003 地点敏感内容边界与历史兼容

- 服务端使用同一个会议文本分析器处理排期校验、公开 Topic 映射和受保护 `meeting-access`，不能由三套正则各自判断。
- 新排期及 PATCH 的 `room` 若包含 HTTP(S)/`www` 链接、会议号/会议码、密码/口令、`passcode`/`pwd` 等凭证线索，返回 `400 SENSITIVE_ROOM_CONTENT`；提示用户把可点击的 HTTP(S) 加入链接填写到“线上会议链接”。
- 普通地点和无秘密的参与说明继续允许；`腾讯会议室 A`、`密码学读书会`、`3号会议室`不得被误判。
- 历史 `room` 中 URL 出现在任意位置时，公开响应不得包含原文本或 URL，统一显示“线上会议”，`hasMeetingUrl=true`；受保护入口提取并返回合法 HTTP(S) URL。历史 `www` URL按 HTTPS 入口兼容。
- 历史 `room` 只有会议号/密码而没有可点击 URL 时，公开响应显示“线上参与信息已隐藏”，`hasMeetingUrl=false`，受保护入口返回 `404`；匿名响应不得包含原数字或口令。
- `/api/topics`、`/api/stats.nextTopic` 以及创建、编辑、认领、排期、归档等所有返回 Topic 的业务响应统一使用同一公开映射。
- 验收矩阵覆盖：普通线下地点、独立 `meetingUrl` 的混合活动、完整 URL、说明文字前后的 URL、`www`、腾讯会议号和中文密码、Teams＋`passcode`、`pwd=`，以及三项 false-positive。
- 浏览器覆盖匿名页面/API/统计不含 synthetic secret；解锁后历史混合 URL 可“加入会议”；把 URL 误填到地点时表单保持打开并显示纠正提示。桌面与 Pixel 7 均需通过。

状态：Accepted（Iteration 016）。

### FR-POSTER-001 一键生成宣讲海报

- 只有排期时间仍在未来的 `SCHEDULED` 卡片显示“生成海报”；过期未归档议题改为“待归档”语义并提示先改期或归档，`OPEN`、`CLAIMED`、`ARCHIVED` 不显示海报入口。
- 点击一次立即在浏览器本地生成 1080×1440 PNG 预览，不请求外部图片或生成服务，不保存可能过期的海报副本。
- 海报包含：炉火品牌、即将开讲、标题、最多三行简介、北京时间日期/星期/时间、分享人、时长、地点/线上提示、最多五个标签、站点来源与品牌标语。
- 标题从 76px 自适应至 48px，最多五行并安全省略；中英文长词均不得越界。
- 海报绝不显示原始会议 URL、会议号、会议码、密码或 passcode。`meetingUrl` 不得进入渲染模型；标题、简介、分享人、标签与旧 `room` 中的 URL/明显凭证也必须先脱敏，绘制层只能接收脱敏后的 `PosterModel`。
- 独立 `meetingUrl` 存在且 `room` 是普通线下地点时，同时显示线下地点与“线上参与 · 会议链接请在议题广场获取”；旧 `room` 本身是 URL 或会议凭证时只显示脱敏提示。
- 预览提供“下载 PNG”；支持文件分享的移动浏览器同时提供“分享 / 保存”。不支持时展示由同一 PNG Blob 创建的图片预览、下载入口与“可长按图片保存”提示。用户取消分享不报错，其他分享失败保留下载入口；弹窗关闭或重新生成时释放 Blob URL。
- 文件名为 `围炉夜话-YYYYMMDD-清理后的标题.png`；PNG IHDR 必须为 1080×1440。
- PNG 图片预览有文本替代；生成期间显示状态，失败后可以重试，不能留下无响应按钮。入口和下载/分享按钮在移动端至少 44px，预览不得造成横向滚动。

### FR-AFF-001 流程入口与数据口径

- “如何围炉”的五个步骤成为按钮：创建议题、筛选待认领、筛选准备中、进入本周已排期、筛选归档。
- 统计卡片可点击进入对应视图；“等待认领”只统计 `OPEN`，`CLAIMED` 单独作为“准备中”语义。
- 原“近期排期”统一改为“已排期”；只有 `NEXT FIRESIDE` 使用未来最近一场语义。
- 主叙事改为“可以自己举起火炬，也可以邀请同伴接力”，不再绝对声称必须由另一个人认领。
- 月历“还有 N 个议题”必须是按钮，点击可展开/收起当天全部事件。
- 标签输入明确“最多 5 个”，超限由服务端错误反馈，不得前端静默截断。
- 私有 GitHub 仓库不得作为公网 Footer 功能链接；仓库公开前移除该死入口。

### FR-ACCESS-001 公网写入保护

- 健康检查、议题列表与统计保持公开；所有业务 `POST`/`PATCH`/`DELETE` 及参与名单、真实会议入口读取需要短期 `X-Fireside-Session`。原始围炉口令只由 `/api/access/verify` 按 SPEC-009/016 验证。
- 服务端使用常量时间比较环境变量 `FIRESIDE_WRITE_KEY`，口令不得进入 Git、日志、URL或错误响应。
- 生产环境缺少口令时拒绝启动，不能静默匿名开放写操作。
- `GET /api/access` 返回是否启用写保护；`POST /api/access/verify` 验证口令但不回传口令。
- 匿名 `GET /api/topics` 不返回 `meetingUrl`；新增 `hasMeetingUrl` 只表达是否有线上入口。旧 `room` 为 URL 时公开响应替换为“线上会议”，原值仅能经受保护入口读取。
- `GET /api/topics/:id/meeting-access` 受口令保护，返回真实会议 URL；页面解锁后通过独立会议入口弹窗获取，避免把密钥或会议凭证写入 URL。
- 浏览器首次协作时输入口令，原始值不保存；`sessionStorage` 只保存 8 小时协作令牌。已知锁定状态下先解锁再打开写表单。任一受保护请求收到 `401` 时只打开一个口令弹窗，保留底层表单但不自动重放请求，解锁后由用户明确重提。
- 口令正确后页面显示“协作已解锁”；错误时给出明确但不泄露细节的反馈。
- 重排也必须携带口令；失败时回滚乐观顺序并同步公开权威快照。参与者重复报名与活动状态变化使用稳定错误码区分，只有状态冲突关闭陈旧名单并刷新。
- Fastify 日志显式脱敏 `x-fireside-write-key`；生产口令保存在 Git 外权限 `0600` 的环境文件中。生产启用顺序必须先安装密钥和 systemd `EnvironmentFile`，再部署拒绝无口令启动的代码。

## 7. API 契约增量

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/access` | 写保护状态 |
| `POST` | `/api/access/verify` | 验证共享口令 |
| `GET` | `/api/topics/:id/meeting-access` | 解锁后读取真实会议入口 |
| `POST` | `/api/topics/:id/release` | 退出认领 |
| `POST` | `/api/topics/:id/unschedule` | 取消排期并清除报名 |
| `POST` | `/api/topics/:id/unarchive` | 撤销误归档 |
| `GET` | `/api/topics/:id/participants` | 获取报名名单 |
| `POST` | `/api/topics/:id/participants` | 报名 |
| `DELETE` | `/api/topics/:id/participants/:participantId` | 取消报名 |

议题列表返回 `participantCount`；Topic 增加 `meetingUrl`。

## 8. 交互和失败恢复

- 生命周期写入期间禁用对应提交按钮，禁止重复请求。
- 所有 `409` 状态冲突关闭陈旧弹窗、提示原因并重新加载权威议题与统计。
- 删除继续只用于误建/重复议题，仅在 `OPEN / CLAIMED` 可用；成熟状态先走取消排期、未举行或撤销归档，确认文案说明永久性与分享人影响（SPEC-017）。
- 弹窗实现 Esc 关闭、Tab 焦点圈、打开后焦点进入、关闭后返回触发按钮。
- 移动端核心触控按钮尽量达到 44px；状态不能只依赖颜色表达。

## 9. 端到端验收矩阵

| 场景 | 验收结果 |
| --- | --- |
| 征集发布 | 返回 OPEN、presenter 为空，卡片出现认领入口 |
| 自荐发布 | 原子返回 CLAIMED、presenter 等于 proposer，无重复认领步骤 |
| 他人接力 | 甲发布、乙认领后同时展示发起人与分享人 |
| 并发认领 | 双客户端恰好一个成功，失败端提示并同步获胜者 |
| 退出认领 | CLAIMED 回 OPEN，只清空 presenter |
| 排期与会议 | 时间/地点/meetingUrl 保存，列表和月/周历一致，链接可进入且不误开编辑 |
| 报名闭环 | 两人报名、重复被拒、取消一人不影响另一人，归档后名单可见且冻结 |
| 改期/取消 | 改期保留名单；取消排期回 CLAIMED、清空排期并删除名单 |
| 归档/撤销 | 归档保存成果；撤销回 SCHEDULED 并清空归档字段、保留名单 |
| 海报 | 未来 SCHEDULED 一键预览/下载 1080×1440 PNG，过期排期无入口；长标题不溢出，所有可绘制字段的会议凭证不泄露，混合活动不丢线下地点 |
| 页面承诺 | 五步、统计、日历溢出、标签限制、会议/资料入口均有真实行为 |
| 写保护 | 匿名写、名单和会议入口返回 401；正确口令成功；公开列表不含会议 secret 或参与姓名，错误口令与日志不泄露 |
| 完整接力链 | 甲征集 → 乙认领 → 排期 → 丙报名 → 入会 → 归档，页面只显示当前可执行动作 |
| 完整自荐链 | 甲自荐发布 → 排期 → 报名 → 海报 → 归档，不经过冗余认领 |
