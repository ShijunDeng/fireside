# SPEC-011：产品操作逻辑、日历活动详情与参与闭环

- 状态：`Accepted`
- 创建：2026-09-02
- 最后更新：2026-09-02
- 依赖：SPEC-001、SPEC-002、SPEC-003、SPEC-004、SPEC-005、SPEC-007、SPEC-008、SPEC-009

## 1. 背景与问题

系统已经具备议题 CRUD、认领、排期、报名、入会、海报与归档 API，但用户看到的入口没有形成同一条完整旅程：页面“报名围炉”承诺可在本周排期中报名旁听或进入会议，实际周历没有报名/查看参与入口，月历事件更只会打开协作者编辑表单。匿名浏览者想先了解活动，也会被管理权限打断。

这不是缺少一个按钮，而是“内容发现、参与活动、协作维护”三种意图没有分层。三路独立业务审计一致把它列为当前最高价值产品缺口；SPEC-007 已接受的月/周历动作矩阵也尚未真正落地，因此成熟度连续无发现计数保持为 0。

本规格先提炼整个系统的操作逻辑，再让列表、月历、周历与页面流程说明共享同一套用户语义。

## 2. 产品角色与信任边界

| 角色 | 用户目标 | 进入方式 | 能力边界 |
| --- | --- | --- | --- |
| 浏览者 | 找到感兴趣的议题和活动 | 公开访问 | 查看公开议题、活动详情、人数、排期与归档成果 |
| 发起人 | 提出一个值得讨论的问题 | 创建时填写公开署名 | 可选择征集他人分享或自己分享 |
| 分享人 | 准备并完成一次分享 | 自荐发布或认领 | 署名表达责任，不代表账号级权限 |
| 参与者 | 报名旁听、参加活动 | 解锁协作后填写公开署名 | 报名/取消；当前共享口令模型不验证个人身份 |
| 协调者 | 排期、纠错、归档和维护内容 | 团队共享口令换取短期会话 | 执行全部写操作、读取名单与真实会议入口 |

当前版本只有“公开浏览 / 已解锁协作”两级信任边界，不声称能证明某个姓名的真实身份。取消任一报名是可信协作者能力，界面不得声称“仅本人可取消”。个人账号、逐人取消凭证、审批流和组织隔离不在本轮引入。

## 3. 整体操作逻辑

### 3.1 发布为什么必须有两条路径

发布议题的人可能只是好奇，也可能已经愿意分享。系统不得强迫“发布者必须等待另一个人认领”，也不得根据姓名猜测意图；创建表单必须显式二选一：

1. **征集分享人（默认）**：创建 `OPEN`，发起人提出问题，分享人为空；之后由任何可信协作者填写分享人并认领。
2. **我来分享**：创建时原子写入 `presenter = proposer`，直接成为 `CLAIMED`，不再让同一用户重复走一次认领。

排期不塞进创建表单。议题内容与分享责任可以由一个人决定，具体时间、地点和会议入口通常需要协调，拆为下一步更清楚，也有独立撤销路径。

### 3.2 生命周期与纠错路径

```text
征集发布 ──> OPEN ──认领──> CLAIMED ──排期──> SCHEDULED ──结束且已举行──> ARCHIVED
               ^              │  ^                  │                         │
               └──退出认领────┘  └──取消排期────────┘                         │
                                      ENDED 未举行 / 重新排期 ────────────────┘
                                      ARCHIVED 撤销误归档 ──> SCHEDULED(ENDED)

自荐发布 ────────────────────> CLAIMED
```

| 状态 / 阶段 | 它表达什么 | 正向动作 | 纠错动作 |
| --- | --- | --- | --- |
| `OPEN` | 有问题，尚无分享责任人 | 认领 | 编辑、删除 |
| `CLAIMED` | 已有分享人，正在准备 | 排期 | 退出认领回 `OPEN`、编辑、删除 |
| `SCHEDULED / UPCOMING` | 已确认未来时间 | 报名、入会、海报、改期 | 取消排期回 `CLAIMED`，同时明确清空报名与会议字段 |
| `SCHEDULED / LIVE` | 活动正在进行 | 迟到报名、入会 | 只允许非时间内容维护，不允许取消或提前归档 |
| `SCHEDULED / ENDED` | 活动已结束，等待结论 | 查看名单；已举行则填写收获并归档 | 未举行则清空旧报名/会议信息回 `CLAIMED` |
| `ARCHIVED` | 已举行并形成沉淀 | 查看名单、资料与收获 | 撤销误归档回原 `SCHEDULED / ENDED` |

删除只用于确实删除议题，不承担退出认领、取消活动或撤销归档等流程纠错。

### 3.3 一条完整用户旅程

1. 发起人发布问题，并明确选择“征集分享人”或“我来分享”。
2. 征集议题由另一位伙伴认领；自荐议题直接进入准备中。
3. 分享人与协调者完善内容，协调者安排未来时间、时长、地点和可选会议入口。
4. 浏览者从列表、月历、周历或“报名围炉”看到公开活动详情，不先被管理表单打断。
5. 用户选择报名时才解锁协作，填写署名；报名后所有视图人数同步。可继续打开受保护会议入口，或为未来活动生成无凭证海报。
6. 活动结束后，协调者二选一：填写收获并归档，或标记未举行并重新排期。
7. 归档保留分享人、原排期、参与名单、收获和资料；误归档可撤销。

## 4. 信息架构决策

### DEC-011-001 活动详情不等于管理编辑

- 点击月历或周历事件必须先打开公开“活动详情”，不得直接触发口令或打开编辑表单。
- 活动详情展示标题、简介、标签、阶段、分享人、日期、时间、时长、地点/安全线上提示和公开报名人数。
- 报名名单、真实会议入口和所有写操作继续使用既有协作会话边界。
- “编辑维护”在详情中作为次级动作，清楚区分参与者与协调者意图。

### DEC-011-002 月历紧凑、周历快捷、详情统一

- 月历日格只承担发现：显示时间、标题、阶段与人数；点击进入统一详情，不在狭小日格堆叠动作。
- 周历在统一详情之外保留高频快捷动作，但必须补齐报名/查看参与和人数，不能只有会议与海报。
- 列表卡继续保留完整动作。三种视图的动作准入都来自同一个阶段矩阵，不能各写一套矛盾判断。

### DEC-011-003 打开详情先使用可见快照，再确认最新 Topic

- 点击后立即打开详情，避免网络等待让入口显得失效；弹窗同时通过公开 `GET /api/topics/:id` 确认最新 Topic。
- 成功后以最新状态、revision、排期和人数替换快照，并同步页面 Topic 集合。
- 已删除返回明确提示并同步移除；已取消排期或状态变化时保留可理解说明，不显示陈旧活动动作。
- 读取失败保留弹窗和当前公开快照，标注“信息可能不是最新”，提供重试，不把失败伪装成成功刷新。

## 5. 功能需求

### FR-DETAIL-001 统一活动详情

仅有排期的 `SCHEDULED` / `ARCHIVED` Topic 从日历进入活动详情。详情必须：

- 使用语义化 dialog、焦点圈、Esc、backdrop、焦点恢复和既有 dialog stack；
- 显示阶段说明，而不只显示技术状态名；
- 公开显示 `participantCount`，不公开姓名或会议 URL；
- 为各动作提供明确文本，不能只有无障碍名称或图标；
- 状态变为 `OPEN` / `CLAIMED` 时提示“活动已取消排期”，只保留返回议题/关闭；
- Topic 被删除时提示“议题已删除”，同步列表并可关闭。

### FR-DETAIL-002 阶段动作矩阵

| 阶段 | 参与动作 | 活动动作 | 协作维护动作 |
| --- | --- | --- | --- |
| `UPCOMING` | 报名/查看参与 | 有入口时加入会议；生成海报 | 编辑维护；取消排期 |
| `LIVE` | 报名/查看参与 | 有入口时加入会议 | 普通编辑；排期时间保持锁定 |
| `ENDED` | 只读查看参与 | — | 完成归档；未举行/重新排期；普通编辑 |
| `ARCHIVED` | 只读查看参与 | 有资料时查看资料 | 编辑维护；撤销归档 |

弹窗、周历快捷动作与列表必须共享该矩阵。过期或并发状态冲突收到稳定错误后，关闭失效子动作、刷新权威 Topic 和人数，详情本身不应无故消失。

### FR-PARTICIPATE-001 从页面承诺完成报名

- “如何围炉 → 报名围炉”进入当前周周历后，用户无需切回列表即可选择活动并完成报名。
- 点击“报名 / 查看参与”沿用现有受保护名单弹窗；解锁后可以打开待确认表单，但不得自动提交报名。
- 成功报名或取消后必须重新读取最新 Topic，并同步详情、列表、月历、周历、统计中的人数/状态。
- 同一名单弹窗内人数先以名单响应为权威；关闭后底层详情已显示最新 `participantCount`。
- `UPCOMING` / `LIVE` 可以报名和取消；`ENDED` / `ARCHIVED` 名单只读。

### FR-CALENDAR-001 月历与周历闭环

- 月历事件 aria-label 使用“查看活动”，不得继续宣称“编辑”。
- 月历事件显示报名人数，点击进入统一详情。
- 周历事件主体进入统一详情，并显示报名人数。
- 周历 `UPCOMING` / `LIVE` 显示“报名 / 查看参与”；`ENDED` / `ARCHIVED` 显示“查看参与”。
- 周历既有会议和海报快捷动作按阶段保留；快捷动作不能触发事件主体的详情点击。
- 当前周完全无活动且存在未来活动时，显示“查看下一场”并把 cursor 移到该活动所在周；没有未来活动时提供“查看待认领议题”。

### FR-MOBILE-001 移动端日期定位和触控

- Pixel 7 进入周历时自动把“今天”列滚入可视区域；点击“今天”即使 cursor 已在本周，也再次定位今天。
- 只在进入周历、切换周期或显式点击“今天”时定位；30 秒阶段刷新、详情同步和报名人数变化不得抢走用户手动横向滚动位置。
- 月历事件、周历快捷动作、详情动作、弹窗关闭和取消报名的触控目标至少 `44×44px`。
- 不产生页面级横向溢出；日历只在自己的滚动容器内横向滚动。

### FR-NAV-001 任务导向的菜单与导航

- 桌面顶栏保持吸顶，主导航为“议题广场 / 本周活动 / 待归档 / 往期回顾 / 如何参与”；权限工具“解锁/退出协作”与唯一主 CTA“发起议题”在视觉和语义上独立。
- “议题广场”必须进入 `ALL + list` 并清除搜索和临时阶段过滤；“本周活动”进入 `SCHEDULED + week + today`；“待归档”进入 `SCHEDULED + ENDED + list`；“往期回顾”进入 `ARCHIVED + list`；“如何参与”到达五步说明。
- 当前目的地使用 `aria-current`；执行导航后把焦点送到目标区域标题，不能只滚动而不建立键盘上下文。
- 移动端不得通过 CSS 隐藏业务导航且不提供替代。顶部保留品牌、“发起”主动作和“菜单”；菜单完整提供与桌面同构的五个目的地和协作状态。
- 移动菜单使用 dialog 语义、Esc/backdrop、焦点圈与关闭后焦点恢复；选择目的地后先关闭菜单，再聚焦目标标题。
- 已解锁且点击会立即退出时，按钮文字必须是“退出协作”，不得仍写成静态“协作已解锁”；认证关闭时显示“协作开放”且不伪装成退出动作。
- 品牌和 Footer 品牌都回到页面顶部；Footer 同时提供议题、活动、往期和如何参与快捷入口。
- Hero 主动作使用明确的“发起议题”，Closing 除发起外提供“认领一个议题”，覆盖两条发布/接力主旅程。

### FR-LAYOUT-001 合理排版与动作层级

- 单页信息顺序保持“价值主张 → 下一场/概览 → 议题工作台 → 如何参与 → 基调 → 最终行动”，但移动端压缩装饰性炉火图和段间距，使下一场或议题入口能在前两屏出现。
- 工作区按“状态范围 → 搜索 → 视图 → 排序/临时任务”分组，并显示当前范围与结果数。互斥状态不能产生必为空的日历：从 `OPEN / CLAIMED` 进入月/周历时自动切到 `SCHEDULED`；`ALL / SCHEDULED / ARCHIVED` 可分别查看全部有日期活动、当前排期和历史活动；进入 `OPEN / CLAIMED` 状态时视图自动切回列表。
- 议题卡只突出当前阶段的主动作；编辑、删除等维护动作降为清晰的次级管理区，不与状态、标题和参与动作争抢同一视觉层级。
- 手机核心正文不小于 12px，辅助元数据不小于 11px；流程说明、卡片动作、月/周事件不能继续使用 8–10px 作为主要阅读文字。Pixel 7 的五步说明改为约 96px 的紧凑步骤行，不用五张大装饰卡拉长复访路径。
- 按钮与输入至少 44px 高；桌面、平板和手机分别使用稳定的双列/单列、工具栏换行和弹窗宽度，不以缩小文字解决空间不足。
- 验收视口至少覆盖 1440×1000、820×1180、Pixel 7；页面级无横向溢出，日历横滑是唯一例外。

### FR-PROMISE-001 五步流程与统计承诺

| 页面承诺 | 真实结果 |
| --- | --- |
| 创建议题 | 打开包含发布意图二选一的创建表单 |
| 认领议题 | 进入 `OPEN`，可选择议题认领 |
| 议题排期 | 进入 `CLAIMED`，可选择议题安排分享 |
| 报名围炉 | 进入当前周，可从活动详情报名/入会 |
| 沉淀归档 | 进入 `ENDED` 待归档任务，而不是只浏览已经归档的历史 |
| 空的 NEXT FIRESIDE“认领一个议题” | 可点击进入 `OPEN`；不得使用 disabled 卡片承诺一个不存在的入口 |

待归档任务使用前端派生 `phase = ENDED` 过滤，不新增持久状态或 API。用户切换普通状态 tab 时清除该临时阶段过滤，并提供可见的“待归档任务”筛选标记与清除动作。

### FR-EMPTY-001 与当前上下文一致的恢复动作

- 搜索无结果：优先“清除搜索”。
- 特殊待归档过滤无结果：提示当前没有待归档活动，并提供“查看已排期”。
- 普通状态筛选无结果：提供“查看全部议题”；只有全站确实无议题时才把“发起议题”作为唯一动作。
- 周历本周无活动按 FR-CALENDAR-001 提供下一场或待认领入口，不能只有七列“留一晚给未知”。

## 6. 数据与 API

本轮不新增表和业务 API。复用公开 Topic 读取、受保护名单与报名、受保护真实会议入口、既有 revision 生命周期命令和本地海报生成链路。

参与记录的唯一约束、阶段守卫、revision 递增和共享协作边界保持不变。前端不得用新增本地状态绕过 API 冲突语义。

## 7. 错误、并发与安全语义

- 详情最新读取 `404`：显示已删除并同步页面；不继续提供旧动作。
- `401`：打开 AccessModal；解锁只恢复“打开子表单/入口”这一导航意图，不自动提交报名或维护 mutation。
- `409 TOPIC_STATE_CONFLICT / ACTIVITY_TIME_CONFLICT`：关闭失效子弹窗，保留详情，刷新最新 Topic、阶段与人数。
- `412 REVISION_MISMATCH`：维护表单使用既有冲突恢复；详情同步最新版。
- 网络失败：不清空已展示公开详情，不错误减少人数；提供重试。
- 详情、月历和周历不得渲染 `meetingUrl`；真实 URL 只能存在于受保护 MeetingModal。

## 8. 验收标准

### 8.1 自动化与浏览器主旅程

桌面 Chrome 与 Pixel 7 均须完成：

1. 从“报名围炉”进入当前周，今天列位于移动可视区。
2. 点击未来活动，匿名先看到公开详情，不出现编辑口令拦截。
3. 点击报名，按既有协作边界解锁；填写唯一署名并报名，名单和详情人数 `+1`。
4. 关闭详情，周历显示新人数；切月历、列表仍显示相同人数。
5. 从月历再次打开同一详情并取消该报名，详情、月历、周历、列表人数恢复。
6. 关闭详情后焦点回到原月/周事件；叠层报名关闭先回详情动作，再关闭详情回日历事件。

### 8.2 阶段与页面承诺

- `UPCOMING / LIVE / ENDED / ARCHIVED` 在详情、周历与列表严格符合动作矩阵。
- 月历点击进入详情而非编辑；“编辑维护”仍可从详情独立进入。
- “沉淀归档”进入 ENDED 任务；选择一项、填写收获、完成归档后出现在历史归档。
- NEXT FIRESIDE 为空时入口可进入待认领；搜索、阶段筛选和本周空日历提供匹配上下文的恢复动作。
- 报名或状态冲突后不展示陈旧按钮，不自动重放写操作。

### 8.3 可访问性与响应式

- 新增动作可通过键盘完成；dialog 名称、初始焦点、Tab 圈、Esc、backdrop、inert 和逐层焦点恢复通过。
- Pixel 7 所有本轮核心触控目标实测至少 `44×44px`，页面 `scrollWidth <= innerWidth`。
- 今天定位不在阶段定时器或人数刷新时重复触发。
