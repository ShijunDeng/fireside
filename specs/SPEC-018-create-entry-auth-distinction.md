# SPEC-018：发起议题与解锁协作入口分离

- 状态：`Accepted`
- 创建：2026-09-02
- 最后更新：2026-09-02
- 依赖：SPEC-008、SPEC-009、SPEC-011、SPEC-013

## 1. 用户问题

锁定状态下，“解锁协作”和所有“发起议题”按钮都会先打开同一个口令弹窗，标题、内容与下一步完全相同。两个外观和文案不同的入口实际没有表达不同任务：用户点“发起议题”后既看不到创建表单，也无法先整理草稿，会合理地认为页面重复或按钮接错。

根因是页面把 `create` 与认领、排期、维护等动作一起放进 `requireAccess`，在建立业务意图之前就要求权限。共享口令保护的是写入，不应阻止用户查看和填写不含敏感数据的创建表单。

## 2. 操作逻辑

### 2.1 两个入口承担不同任务

- **解锁协作**：只打开“解锁围炉协作”口令弹窗，不创建议题草稿、不打开业务表单；成功后仅改变当前标签页的协作状态。
- **发起议题 / 发起**：在协作状态读取完成后，无论当前是否解锁，都立即打开“发起一个新议题”表单，展示标题、简介、发起人、标签和“征集分享人 / 我来分享”二选一；不得先显示口令弹窗。
- 协作状态仍在初始化时，创建表单可以打开，但提交只提示“正在确认协作状态”，不得误发写请求。

### 2.2 先写草稿，发布时验证

- 未解锁的创建表单显示说明：“可以先填写草稿；发布时再用围炉口令解锁，系统不会自动提交。”
- 用户首次点击“发布议题”时若仍锁定，不发送 `POST /api/topics`，而是在创建表单之上打开 AccessModal；底层表单 inert，全部字段和发布意图保留。
- 关闭口令层回到原创建表单，焦点恢复到“发布议题”；草稿不丢失。
- 正确解锁只关闭口令层并恢复底层创建表单，不自动发布。用户检查内容后必须再次点击“发布议题”，这次只发送一个创建请求。
- 错误口令、限流、Esc、X 或遮罩均不得提交议题或清空草稿。
- 页面自认为已解锁但服务端返回真实 `401` 时，继续沿 SPEC-009 的失效会话叠层与显式重提契约。

### 2.3 其他动作与安全边界

- 本规格只调整 `create` 入口；参与名单、真实会议入口和需读取敏感值的维护动作继续先走既有权限边界。
- 创建表单只使用公开字段，不读取报名姓名、会议 URL、原始口令或会话令牌。
- 认证关闭时保持直接创建；后端仍是最终写入权限边界，前端提示不能替代服务端 401。

## 3. 可访问性与反馈

- 创建表单和口令弹窗保持两个可区分的 dialog 名称；任何时刻只有顶层可交互。
- 从创建表单打开 AccessModal 后，底层 inert、body 滚动锁只计一次；关闭/解锁后焦点回“发布议题”。
- 直接“解锁协作”关闭后焦点回原解锁按钮；不得意外出现创建表单。
- 桌面、平板和 Pixel 7 不横向溢出，锁定说明使用可感知的状态文本但不抢输入焦点。

## 4. 验收

1. 锁定状态分别点击“解锁协作”和“发起议题”：前者只有 AccessModal，后者只有创建表单；dialog 名称和字段明显不同。
2. 在锁定创建表单填写全部字段和“我来分享”发布意图，首次点发布后看到两层 dialog，`POST /api/topics` 计数仍为 0；底层标题、简介、发起人、标签和发布意图完整且 inert。
3. 用 Esc、X、遮罩和错误口令关闭/停留口令层，均不写入；回到底层时焦点、草稿和错误语义稳定。
4. 正确解锁后仍为 0 个创建请求，创建表单保留；第二次显式点击发布恰好一次 201，“我来分享”必须得到 `CLAIMED`、分享人=发起人且标签完整的卡片。
5. 会话真实过期时的 401、429 与叠层回归继续通过；认证关闭时直接创建。
6. 桌面 Chrome 与 Pixel 7 无重试覆盖入口分离、两层 dialog、草稿、焦点、请求计数和无横向溢出；全量 check、构建和依赖审计通过。

## 5. 非目标与后续

- 本轮不改个人账号模型，不把共享口令持久化，也不自动发布。
- 是否让认领、排期等更多公开字段表单也采用“先填后解锁”，留待独立业务审查；不能在未评估敏感读取和并发恢复前一并放开。
- 本修复来自用户直接发现，成熟度连续无新增有效轮次保持 0；完成后继续既定业务循环。

## 6. 实现与验收记录

- `create` 不再被入口级 `requireAccess` 拦截；锁定状态允许打开公开字段表单，首次发布由 kind-aware 重锁门禁叠加 AccessModal。其他业务表单重锁时使用通用保留文案，不会误称“议题草稿”。
- 已知锁定时的再次提交不会发出注定失败的业务 401；首次真实 401 仍清理失效会话、叠加口令层并保留草稿。正确解锁、限流恢复都不自动重放，最终只由显式再次发布写入。
- 桌面 Chrome 与 Pixel 7 定向验收 4/4，覆盖入口分离、双 dialog/inert、Esc/X/遮罩、短口令、草稿/标签/“我来分享”保留、零自动写入与最终 `CLAIMED`。三路独立终审 clean。
- 全量证据与 SPEC-013 共享：154 项 `check`、80 项无重试跨端 E2E 通过、4 项按设备职责跳过，构建、差异检查和 0 漏洞审计通过。
