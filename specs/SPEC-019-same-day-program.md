# SPEC-019：同日多场日程编排与海报场次上下文

- 状态：`Implementing`
- 创建：2026-09-02
- 最后更新：2026-09-02
- 依赖：SPEC-002、SPEC-004、SPEC-005、SPEC-006、SPEC-007、SPEC-008、SPEC-011、SPEC-014

## 1. 用户问题与确定性现状

用户追问：同一天有多个议题时，海报如何排版，日历如何展示，系统是否有完整应对策略。

现有页面会在月历显示最早三条并内联展开全部，周历则直接显示全部；这只覆盖少量同日议题。当天达到 10 场时，月历整周被无界撑高，周历单列也过长；日头没有总场次，重复快捷动作的无障碍名称无法指明所属活动。

更重要的是，服务端的排期和改期没有任何跨 Topic 时间区间检查，可以把两场单轨围炉排在完全相同的时间。单场海报只写“即将开讲”，无法告知这是当天第几场；文件名只有日期和标题，同日同名会相互覆盖。

## 2. 产品决策

### DEC-019-001 单轨、同日可串行联场

- “围炉夜话”当前是一个面向同一社群的单轨活动，没有 track、会场或资源模型。
- 允许同一北京时间自然日安排多场，但必须串行。区间使用半开语义 `[start, start + duration)`；前一场结束时间恰好等于后一场开始时间时允许，任何 1ms 重叠都拒绝。
- 区间判定使用绝对时间，所以跨午夜和不同 offset 仍正确检测；不依赖自由文本地点判断是否可并行。
- 未来如需并行分会场，必须先新增正式 track/resource 模型和其容量、报名、导航规格；本规格不用 `room` 猜测。

### DEC-019-002 海报一题一张，不把完整日程硬塞进单场模板

- 单场海报继续以某个准备进行的 Topic 为主角，保留标题、简介、分享人和地点的阅读空间。
- 同日有多场可宣传 Topic 时，顶部徽标显示“当日第 N / M 场”；单场时仍显示“即将开讲”。场次基于刚刚重新读取的公开同日快照，无法确认时宁可不显示 N/M，不伪造过期场次。
- 海报显示公开 Topic 编号；文件名为 `围炉夜话-YYYYMMDD-HHmm-topicId-标题.png`，同日同名也不覆盖。
- “当日联场海报”、二维码和公开深链需要独立容量和路由规格，不在本轮中暗中加入。

## 3. 服务端排期契约

### FR-SCHEDULE-019 原子防重叠

- `POST /api/topics/:id/schedule` 与已排期 Topic 的时间/时长 PATCH 都在 SQLite `IMMEDIATE` 事务内重读目标、检查 revision/阶段、读取其他 `SCHEDULED` 区间、判定重叠并写入。不允许“先查再在事务外写”。
- PATCH 只在 `scheduledAt` 或 `duration` 实际改变时执行重叠检查；普通内容/地点更新不受影响。
- 重叠返回 `409 ACTIVITY_SCHEDULE_OVERLAP`，响应包含稳定文案与 `conflicts: [{ id, title, scheduledAt, duration }]`；只返回公开字段，按开始 epoch、ID 排序，不包含报名姓名、会议入口或会话信息。
- 优先级保持：认证/503/parser/If-Match → 404 → 目标 revision 412 → 目标状态/阶段 409 → 候选时间 400 → overlap 409 → 成功。
- 重叠拒绝后目标与冲突 Topic 的全部字段、revision、updatedAt、排序版本和报名名单零变化。释放时段后，失败方可用原 revision 调整时间并显式重试。
- 现有数据不自动删改。页面从公开列表检测历史重叠并标记“排期重叠·待改期”；冲突解决前不为相关 Topic 生成新海报。

### FR-SORT-019 统一时区与稳定顺序

- 业务日、“今天”、日历时间标签、排期表单和海报统一使用 `Asia/Shanghai`，页面明示“北京时间”。跨午夜活动归入开始日。
- 同日事件、当日日程、API `sort=schedule`、海报场次和 NEXT 选择都使用 `(startEpoch ASC, id ASC)`；不按带 offset 的原始 ISO 字符串直接比较。
- 页面的 NEXT 从已读取 Topic 和当前时钟派生，跨过开始边界后不继续把 LIVE 活动称为“下一场”；同日多场时显示“当日共 M 场”。

## 4. 日历与当日日程

### FR-CALENDAR-019 有界预览与完整日程

- 月历和周历的日头都显示“M 场”；0 场继续使用安静空状态。
- 两种日历每日最多显示最早 3 场完整预览。第 4 场起显示“另有 N 场”/“查看当日全部 M 场”，打开“X月X日（周X）·M 场围炉” dialog；不再把全部事件内联塞回日格/周列。
- 当日日程完整展示 0/1/3/4/10 场边界下的全部活动，每行包含北京时间始末、阶段、标题、分享人、安全地点和公开报名数。点击行叠加既有活动详情，关闭详情回原行，关闭日程回“查看全部”入口。
- 更多入口使用 `aria-haspopup="dialog"` 和包含日期/总数的 aria-label；快捷动作名称加入开始时间和标题，不让辅助技术面对多个无法区分的“报名 / 生成海报”。
- dialog 复用 SPEC-008 弹窗栈；底层 inert、Esc/X/backdrop 只关顶层、焦点往返正确，Pixel 7 核心触控目标至少 44px，页面不横向溢出。

## 5. 海报与页面恢复

### FR-POSTER-019 单场场次上下文

- 打开海报后继续重新 GET 目标 Topic，并读取当前公开排期列表以确定当日场次/历史重叠。目标 GET 失败仍拒绝生成；同日列表失败时可生成不带 N/M 的安全单场海报。
- 2 场以上显示“当日第 N / M 场”，1 场显示“即将开讲”；预览摘要、替代文本和 Canvas 都包含公开 Topic 编号，不包含会议凭证。
- 新文件名同时包含北京时间日期、时分、Topic ID 和脱敏标题；保持 1080×1440、极限布局、Unicode 凭证脱敏、Blob 释放和下载/分享回归。
- 检测到目标与另一个现有 `SCHEDULED` 区间重叠时，不生成新海报，显示“排期重叠，请先改期”并同步日历标记。

### FR-RECOVERY-019 重叠错误不丢表单

- 排期或改期收到 `ACTIVITY_SCHEDULE_OVERLAP` 时保留当前表单、开始时间、时长和报名影响确认层，在当层显示冲突议题/时段并聚焦错误。
- 该 409 不走“状态已变化”通用关闭流程，不自动重试。页面可在不覆盖草稿的前提下同步公开列表；用户调整后再次显式提交。

## 6. 验收矩阵

1. 单元：北京时间日键/表单转换，跨午夜归属，`[start,end)` 相邻允许与 1ms/同起点/时长扩张重叠，不同 offset 同一绝对时段，`(epoch,id)` 稳定排序。
2. API：schedule 和 PATCH 返回结构化 overlap 409，前后完整快照/名单/排序不变；陈旧 revision+重叠仍先 412，目标阶段错误仍先于 overlap。
3. 并发：同一目标并发改期恰好一次成功+一次 412；不同目标竞争同一时段恰好一次 200+一次 overlap 409；释放时段后失败方用原 revision 成功。
4. 日历：同日 0/1/3/4/10 场，最早三条预览、总数和完整日程无遗漏；北京与洛杉矶时区运行下归属/顺序一致；dialog 栈、焦点、44px 和无横向溢出通过。
5. 页面错误：排期和有报名改期确认分别命中 overlap，冲突场次可见且聚焦，草稿/人数/变更对照不变，调整后单请求成功。
6. 海报：单场与同日第 N/M 场徽标不截断；两个同日同名 Topic 文件名不同；Topic ID、时间和 alt 正确，原有脱敏/布局/PNG 验收不回归。历史重叠不生成新海报。
7. 全量 `npm run check`、无重试桌面 Chrome/Pixel 7 E2E、生产构建、差异检查、依赖审计和三路独立终审通过。

## 7. 非目标与后续

- 本轮不新增并行 track/会场资源、全天一键报名、全天一键归档、当日联场海报、二维码或公开深链。报名和归档仍按 Topic 独立完成。
- 少于某个组织间隔（例如 10 分钟）不做任意服务端硬拦截；只保证不重叠。如需换场准备时间，应以独立可配置规格进入后续轮次。
- 取消排期前可操作的通知名单、往期按日期分组与当日联场海报仍是独立候选；完成本规格不停止成熟度循环。
