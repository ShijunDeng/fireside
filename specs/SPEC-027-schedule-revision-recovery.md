# SPEC-027：排期 revision 冲突的草稿恢复

- 状态：`Accepted`
- 创建：2026-09-02
- 优先级：P2
- 关联：SPEC-005、SPEC-013、SPEC-019、SPEC-025

## 1. 已复现

用户在自荐/认领后的排期转场或准备中卡片填写时间、时长、地点和会议入口；另一协作者先修改议题使 revision 前进；提交 `/schedule` 得到 412。当前通用冲突分支关闭弹窗并全量刷新，合法排期草稿全部丢失，违反 SPEC-025 的失败保留要求。

## 2. 规则

- `schedule` 收到 `TOPIC_REVISION_CONFLICT` 后读取最新 Topic；仍为 `CLAIMED` 时保持原弹窗和 DOM 草稿，更新本地 revision，显示并聚焦“排期尚未提交”的恢复说明。
- 读取成功的最新 Topic 同时合并进页面权威列表，但不得用其排期字段覆盖当前弹窗里的 DOM 草稿；用户此时关闭，底层卡片必须已经展示最新版，下一次维护使用最新 revision。
- 用户必须显式再次提交；不自动重放，不重复创建/认领。
- 最新状态不再是 `CLAIMED` 时关闭失效表单并同步权威状态；404 移除已删除议题；最新读取失败则保留草稿并提供明确错误。
- 重试仍执行未来时间、单轨防重叠与全部既有校验。

## 3. 验收

自荐转场、认领转场和直接排期共享恢复逻辑；412 后四类排期字段不变、错误聚焦、底层卡片同步远端修改、一次点击一次请求；关闭后再次维护不重复遭遇同一旧 revision，或基于最新 revision 显式重试成功。桌面与 Pixel 7 通过。
