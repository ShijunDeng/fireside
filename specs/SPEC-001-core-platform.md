# SPEC-001：围炉夜话核心平台

- 状态：`Accepted`
- 首次实现：2026-09-01
- 最后更新：2026-09-01
- 追溯提交：`80df708`、`c294e4b`、`99cd4d7`

## 1. 背景与目标

团队需要一个符合“围炉夜话”文艺火炬调性的轻量协作平台，把零散的好奇转化为可执行、可沉淀的分享活动。

目标：

- 让任何成员提出一个值得探索的问题。
- 让发起人选择邀请另一位成员接力，或自己成为分享人。
- 将认领后的议题安排到具体时间与地点。
- 在分享结束后沉淀收获与资料。
- 保持“不做培训、不做考试、不等专家”的低门槛氛围。

非目标：

- 本规格不包含登录、权限、审批、通知和多人组织隔离。
- 本规格不包含日历视图和通用编辑/删除；由 SPEC-002 定义。

## 2. 用户角色

- **发起人**：创建议题，描述问题与探索方向。
- **分享人**：认领议题或在发布时自荐，准备并完成一次分享；可以与发起人是同一人。
- **组织者**：安排分享时间、地点并在结束后归档。
- **围观者**：浏览、搜索、筛选议题和查看归档成果。

当前版本不做身份认证，角色由操作时填写的名称表达。

## 3. 功能需求

### FR-CORE-001 创建议题

- 必填：标题（1–80 字）、简介（1–500 字）、发起人（1–30 字）。
- 可选：最多 5 个标签，每个标签 1–20 字。
- 默认以“征集分享人”发布并进入 `OPEN`；选择“我来分享”时按 SPEC-004 原子进入 `CLAIMED`。

### FR-CORE-002 认领议题

- 只有 `OPEN` 议题可以认领。
- 认领人必填，1–30 字。
- 成功后写入分享人并转为 `CLAIMED`。
- 重复认领必须返回冲突，不能静默覆盖。

### FR-CORE-003 议题排期

- 只有 `CLAIMED` 议题可以排期。
- 必填：ISO 8601 时间、10–240 分钟时长、1–60 字地点或会议说明。
- 成功后状态转为 `SCHEDULED`。

### FR-CORE-004 议题归档

- 只有 `SCHEDULED` 议题可以归档。
- 必填：1–1000 字收获摘要。
- 资料链接可选，仅允许 `http` 或 `https`。
- 成功后状态转为 `ARCHIVED` 并记录归档时间。

### FR-CORE-005 浏览与发现

- 首页展示全部议题卡片。
- 支持按 `OPEN`、`CLAIMED`、`SCHEDULED`、`ARCHIVED` 筛选。
- 支持在标题、简介、人员与标签中搜索。
- 卡片展示与状态相关的人员、排期、地点、时长、收获和资料。

### FR-CORE-006 数据概览

- 展示待认领（`OPEN + CLAIMED`）、近期排期和归档数量。
- 展示未来时间最近的一场已排期议题。

### FR-CORE-007 站点视觉与身份

- 视觉沿用原始 HTML 的深色、暖橙炉火与冷青点缀。
- 桌面和移动端均可读、可操作。
- 浏览器标签页必须展示与页面火焰标识一致的 SVG favicon。
- 提供 Web App manifest，名称为“围炉夜话”。

### FR-CORE-008 生产部署

- 服务监听 `0.0.0.0:80`。
- 使用 systemd 开机启动并自动重启。
- 数据库默认持久化到 `data/fireside.db`，不得提交业务数据库文件。
- GitHub 使用 SSH remote，主分支为 `main`。

## 4. 生命周期状态机

```text
OPEN ──认领──> CLAIMED ──排期──> SCHEDULED ──归档──> ARCHIVED
```

- 状态只能按上图前进。
- 非法越级操作返回 `409 Conflict`。
- 不存在的议题返回 `404 Not Found`。
- 状态转换必须在数据库更新条件中校验前置状态，保证并发原子性。

## 5. 数据模型

`topics` 表核心字段：

| 字段 | 类型 | 约束/用途 |
| --- | --- | --- |
| `id` | INTEGER | 主键，自增 |
| `title` / `summary` | TEXT | 标题与简介 |
| `proposer` / `presenter` | TEXT | 发起人与分享人 |
| `tags` | TEXT | JSON 字符串数组 |
| `status` | TEXT | 四态 CHECK 约束 |
| `scheduled_at` | TEXT | ISO 8601 时间 |
| `duration` / `room` | INTEGER / TEXT | 时长与地点 |
| `takeaway` / `material_url` | TEXT | 归档内容 |
| `created_at` / `updated_at` / `archived_at` | TEXT | 审计时间 |

SQLite 启用 WAL 和外键约束。

## 6. API 契约

| 方法 | 路径 | 需求 |
| --- | --- | --- |
| `GET` | `/api/health` | 健康检查 |
| `GET` | `/api/topics` | 获取与筛选议题 |
| `POST` | `/api/topics` | FR-CORE-001 |
| `POST` | `/api/topics/:id/claim` | FR-CORE-002 |
| `POST` | `/api/topics/:id/schedule` | FR-CORE-003 |
| `POST` | `/api/topics/:id/archive` | FR-CORE-004 |
| `GET` | `/api/stats` | FR-CORE-006 |

错误响应统一为 `{ "message": "可理解的中文错误" }`。

## 7. 非功能需求

- TypeScript 必须通过严格类型检查。
- 所有输入在服务端验证，前端验证不能代替后端验证。
- React 默认转义所有用户文本；资料 URL 限制协议。
- 尊重 `prefers-reduced-motion`。
- 生产依赖不得存在 moderate 及以上已知漏洞。

## 8. 验收与证据

- API 自动化覆盖创建 → 认领 → 排期 → 归档完整路径。
- 自动化覆盖重复认领、越级排期和缺少必填字段。
- 桌面 `1440×1000` 与移动端 `390×844` 完成全页截图验收。
- `npm run check` 通过；`npm audit --audit-level=moderate` 为 0。
- systemd 状态为 `active`，本机 `/api/health` 返回 `ok: true`。
- GitHub Actions 对主分支执行相同的 `npm run check`。

## 9. 已知外部限制

公网访问还依赖华为云安全组放行 TCP 80；应用本身不持有修改云安全组的临时权限。2026-09-02 实机复核确认应用与 PID 1 已监听 `0.0.0.0:80`，本机健康、主机防火墙均正常，但五个独立公网探针和公网回连全部超时；metadata 的临时安全凭证端点返回 401，本机也没有云控制面凭据。因此当前公网可达性仍是未关闭的外部 P1，不能宣称站点已对公网开放。验收必须由至少两个独立公网网络对 `http://166.108.239.81/health` 和首页取得 200，并让多地区 TCP 80 探测成功。
