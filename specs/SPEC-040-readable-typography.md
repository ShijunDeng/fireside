# SPEC-040：全站业务文字可读性与字号层级

- 状态：`Accepted`
- 创建：2026-09-02
- 优先级：P2
- 关联：SPEC-011、SPEC-015、SPEC-021、SPEC-022、SPEC-024、SPEC-031

## 1. 问题与范围

首页统计入口中的“等待认领 / 准备中 / 已排期 / 知识归档”承担主要导航和状态判断，却仅为 9px；页面中还存在以 9–11px 承载操作、错误、帮助、日历身份和活动元信息的情况。命中区即使达到 44px，文字仍会因过小而难以识别。

本规格覆盖桌面、平板和移动端的顶部/移动导航、首页统计入口、议题筛选与状态、卡片、排序和视图切换、月历/周历/当日议程、流程入口、表单、错误与恢复、活动/报名/海报弹窗、页脚。海报图片内部排版仍由 SPEC-006 管理。

## 2. 信息层级规则

- 中文业务导航、筛选、按钮、表单标签、状态名称和可执行恢复文字：桌面计算字号不得小于 13px；窄屏不得小于 14px。
- 正文、业务说明、错误、成功反馈和影响确认：桌面不得小于 13px；窄屏不得小于 14px，并保持至少 1.5 行高。
- 时间、地点、人数、分享人等理解活动所必需的次要元信息：桌面不得小于 12px；窄屏不得小于 13px。
- 纯装饰且不影响理解/操作的英文 eyebrow、序号、品牌副标可以使用 9–11px，但必须与业务文字在 DOM 与视觉层级上分离，不能用作唯一信息来源。
- 不以浏览器缩放、transform 放大或只改字重替代真实 `font-size`；字号提高后仍须保持 320px 无页面级横向溢出、长文本可换行、日历局部滚动和 44px 操作命中区。

## 3. 本轮最低修正面

- 首页四个可点击统计入口的业务名称提升到至少 13px，说明提升到至少 12px；移动端名称至少 14px、说明至少 13px。
- 议题 Tabs 与卡片/日历/当日议程的状态文字属于操作或状态，不得低于对应断点下限。
- 表单标签、提交按钮、错误/重试、名单、取消/改期影响确认和活动详情动作不得低于业务文字下限。
- 月历/周历中的时间、人数、地点以及完整当日议程元信息不得低于元信息下限；高密度优先换行或局部滚动，不通过缩小关键文字解决。
- Toast 和不可用/恢复说明属于结果反馈，不得作为装饰小字处理。
- 顶部任务导航、Hero 主/次 CTA 与页尾 Closing CTA 是最高层业务入口，任何视口真实字号均不得低于 14px；不能出现主要入口反而小于 Tabs 或卡片动作的倒置层级。
- 议题搜索输入与“清除条件”是高频筛选操作，四个目标视口均使用至少 14px 的 action 字号；placeholder 与真实输入不得用更小字号伪装密度。

## 4. 验收

- 自动化浏览器在 1440px、820px 和 Pixel 7 三个视口抽查上述每一类代表元素的 `font-size`，均满足层级下限。
- 四个首页统计入口、议题 Tabs、状态徽标、表单与错误恢复、月/周历、当日议程、详情动作在三端可读且功能不回退。
- 顶部任务导航（可见时）、Hero 两项 CTA 与页尾两项 CTA 在 1440、820、393、320 四视口 computed font-size 均不低于 14px，保持单行/合理换行和 44px 命中区。
- 1440、820、393、320 四视口的搜索输入/placeholder 和出现时的“清除条件” computed font-size 均不低于 14px；筛选工具栏不溢出，命中区仍不少于 44px。
- Pixel 7 与 320px 页面 `scrollWidth <= clientWidth`；长议题、长地点、长状态上下文仍不遮挡或截断唯一业务信息。

## 5. 非目标

- 不把所有文字机械统一为同一字号；保留标题、正文、元信息和装饰文字的层级。
- 不改变现有品牌配色、业务流程、数据结构或海报画布的视觉比例。
