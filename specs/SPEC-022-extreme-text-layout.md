# SPEC-022：合法极端文本的卡片与海报布局边界

- 状态：`Accepted`
- 创建：2026-09-02
- 优先级：P1
- 关联：SPEC-002、SPEC-006、SPEC-011、SPEC-017、SPEC-019、SPEC-021

## 1. 可复现问题

API 合法接受 80 字符标题、30 字符姓名和 20 字符标签。标题为无空格连续 Latin 字符时，当前双列 Grid 使用内容最小宽度扩张：桌面卡片 `scrollWidth` 可超过 4,000px，Pixel 7 卡片内容被 `overflow:hidden` 静默裁掉。未来排期生成海报后，连续标题还会把海报 Grid 的右列撑宽到约 1,500px，使预览和下载按钮跑出移动视口，并让桌面/平板弹窗内部横向溢出。

现有极端海报测试主要使用可自然换行的汉字，删除确认测试只验证弹窗，没有验证列表卡片和海报 Grid，因此未覆盖连续文本边界。

第 37 轮独立 UI 审查进一步以合法上限的 78 字标题、500 字简介和 1000 字归档收获验证列表可扫描性：已排期卡在 1440/820/393/320px 视口分别高约 998/1382/1503/1895px，归档卡分别高约 1620/2427/2806/3745px。虽然文字不再横向溢出，但一张归档卡可占据五个以上手机视口，其他议题和操作入口被推到很远；“可换行”不能替代“可扫描”。

## 2. 决策与范围

- 所有用户可写文本容器必须允许 Grid/Flex 子项收缩；标题、简介、姓名、标签和海报摘要对连续文本使用 `overflow-wrap:anywhere`。
- 议题双列使用 `minmax(0,1fr)`，卡片、页脚人员区、海报左右列和摘要明确 `min-width:0`。
- 海报图片保持比例并限制在预览列宽内；不通过裁掉文字、缩小按钮或让整页横向滚动规避问题。
- 不改变 API 长度上限、Canvas 的省略预算、海报尺寸、文件名或凭证脱敏。
- 列表卡片是扫描入口，不承担默认展示全部正文：简介默认限制 4 行，归档“炉边余温”正文默认限制 5 行；活动详情仍完整展示正文。
- 默认先应用真实 4/5 行布局，再以 DOM 的 `scrollHeight > clientHeight` 判断该视口是否溢出；禁止用字符数猜测行数。仅当实际溢出时出现与正文一一对应的“展开/收起”按钮。按钮必须有明确的 `aria-controls`、`aria-expanded`，命中高度不少于 44px，字号不少于 14px；同一按钮持续存在以保持键盘焦点。
- 正文、字体或可用宽度变化时必须重新测量；测量过程不能截断存储内容、制造可见闪烁或在展开态误删控制按钮。
- 展开态只属于当前正文语义版本：撤销归档清空旧余温、从非归档进入新归档，或归档余温正文被替换时，新正文必须从默认 5 行折叠态开始。相同正文的列表刷新、排序或普通 revision 更新不得折回用户正在阅读的内容。
- 展开只影响当前卡片、不得改变筛选/排序/状态或触发网络写入；收起后恢复扫描高度，完整文本始终保留在 DOM 与活动详情中。
- 收起发生在长正文底部时，浏览器不会自动补偿上方大段内容消失造成的滚动偏移。系统必须在布局收缩后把仍然聚焦的同一展开按钮校正到可视区，顶部至少避开吸顶导航 8px、底部保留 8px；不得跳到其他卡片或使用平滑滚动制造二次漂移。

## 3. 验收标准

1. 桌面 Chrome 与 Pixel 7 使用 80 字连续 Latin 标题、30 字连续分享人和合法长标签，列表卡片 `scrollWidth <= clientWidth`，标题可读换行且整页不横溢。
2. 同一未来排期一键生成海报后，dialog、预览列、摘要列与操作区均不发生内部横溢；图片和“下载 PNG”按钮完整位于 dialog/视口内，核心按钮保持至少 44px。
3. 海报仍为 1080×1440，Canvas 极限布局、凭证脱敏、同日 N/M 和唯一文件名回归不变。
4. 820px 月/周局部滚动只能出现在日历容器，不得被本修复影响。
5. TypeScript、单元/API、生产构建和全量跨端 E2E 通过。
6. 1440、820、393、320px 四档视口下，500 字简介与 1000 字归档收获在列表默认态均实际发生视觉折叠，单张卡不再占据多个完整视口且整页无横向溢出。
7. 展开简介/余温后完整合法文本可读；按钮的可访问名称、展开状态和控制目标一致，鼠标与键盘均可操作，展开、收起后的焦点保持在原按钮且无横向溢出。
8. 普通短内容不出现多余展开按钮；列表态折叠不影响海报、活动详情、归档编辑或资料入口。
9. 在 1440、820、393、320px 将展开正文底部的“收起”按钮滚入视口后点击，布局稳定后同一“展开”按钮既保持焦点也完全位于可视安全区；简介与炉边余温分别覆盖，页面不跳到其他议题。
10. 恰好 160 字中文简介与 220 字中文余温在四档视口中按真实 4/5 行边界判断：凡实际溢出都有折叠和控制，凡完整落在边界内不显示多余控制；同一页面改变视口宽度后结果会重算。
11. 在“全部议题”列表展开旧余温后执行撤销归档，再对同一议题完成新归档：旧余温已清空，新长余温默认 5 行、按钮为“展开炉边余温”且 `aria-expanded=false`；详情/编辑显示新全文。相同正文的只读刷新或排序仍保留用户当前展开态。

- 同日多场海报桌面定向复跑通过；移动端在此前全量中也通过，证明列表渐进披露未改变海报场次与文件名语义。
