# SPEC-021：平板月历与周历横向可达

- 状态：`Accepted`
- 创建：2026-09-02
- 优先级：P1
- 关联：SPEC-002、SPEC-011、SPEC-015、SPEC-019

## 1. 可复现问题

在 820×1180 视口进入月历或周历时，内容容器宽约 770px，但月历和周历分别固定最小宽度 860px、980px。横向滚动只在 `max-width:720px` 启用，外层 `.calendar-shell` 又使用 `overflow:hidden`，所以平板用户看不到也无法滚到右侧日期、议题和操作。

既有“平板宽度”浏览器测试只验证菜单和页面级无横向溢出，没有实际进入月历/周历，因此未捕获该功能阻断。

## 2. 决策与范围

- 月历、周历的直接滚动容器在所有视口都使用 `overflow-x:auto`。宽屏内容未溢出时不出现无意义滚动；平板和手机溢出时由局部容器承接，不把整页撑宽。
- 保留月历 860px、周历 980px 的信息密度，不把七列强压到不可读宽度。
- 不改变列表、日期归属、同日三条预览、完整当日日程或“今天”定位语义。
- 本轮不重新设计为单列移动日程；局部横向滚动是修复现有七列产品的最小完整方案。

## 3. 验收标准

1. 820×1180 Chromium 中，进入月历后滚动容器 `scrollWidth > clientWidth` 且 `overflow-x=auto`，可从最左滚到最右，右侧日期列完整进入容器可视范围。
2. 同一视口进入周历，满足相同条件，周日列和其中的议题/空态可达。
3. 月历与周历的局部滚动不会导致 `documentElement.scrollWidth > innerWidth`；顶部任务导航和工作区仍不发生页面级横向溢出。
4. Pixel 7 的“今天”定位、44px 核心控件及同日完整议程回归不变；桌面宽屏不出现裁切。
5. TypeScript、全量单元/API、生产构建及桌面/移动 E2E 通过。
