# SPEC-006：宣讲海报隐私、极限布局与最新快照

- 状态：`Accepted`
- 创建：2026-09-02
- 优先级：P1
- 关联：SPEC-003 第 10 轮、SPEC-004 FR-POSTER-001、SPEC-005 Topic revision

## 1. 问题与目标

现有海报脱敏只识别少量 ASCII 凭证。合法业务字段中的中文密码、入会码、`pwd` 和分段会议号仍会进入预览、PNG 与文件名；页面却明确承诺“线上会议链接与凭证不会出现在海报中”。下载或分享后的海报无法撤回，属于可由正常录入触发的隐私泄漏。

极限合法内容也没有共享的纵向布局预算：80 字中文标题会把标签区推入固定页脚；最长标签的胶囊宽度虽然被限制，文字本身没有省略或裁剪，第五个标签还可能被静默丢弃。海报弹窗同时直接使用列表快照，与“使用最新排期”文案不符。

本规格的目标是：

1. 所有可绘制字段与下载文件名使用同一套 Unicode 凭证脱敏规则，不留下分段残片。
2. 所有服务端允许的最大输入都能生成结构完整、区域不重叠的 1080×1440 PNG。
3. 五个合法标签全部可见，标签文字不会越出胶囊或相互覆盖。
4. 点击“一键海报”后先读取最新 Topic，只根据该快照判断资格和生成；陈旧入口、状态变化与读取失败均可恢复。
5. 桌面 Chrome 与 Pixel 7 的预览、下载、失败恢复和隐私边界一致。

## 2. 确定性复现基线

旧实现必须由回归测试固定以下失败，修复后逐项转绿：

| 输入 | 旧结果 |
| --- | --- |
| `入会码：火炬` | 原样保留 |
| `密码：秘密口令` | 原样保留 |
| `口令：围炉` | 原样保留 |
| `pwd=omega` | 原样保留 |
| `会议号：123 456 789` | 只隐藏首段，残留 `456 789` |

布局基线使用 80 个中文字符作为标题、能铺满三行的 500 字简介、30 字分享人和五个各 20 字的标签。旧等宽测量可稳定得到五行标题、`tagBottom=1268`，而固定品牌标语基线为 `1266`；标签与页脚直接重叠。五个最长标签还会因逐项固定上限和 `break` 逻辑少绘制一个。

## 3. 统一隐私规则

### FR-PRIVACY-001 可识别凭证语法

匹配不区分英文大小写，并支持半角/全角冒号、等号、井号、空格、制表符、标签与值之间的换行，以及 `()`、`（）`、`[]`、`【】`、`〔〕` 等成对括号。左括号可作为标签和值的边界，匹配必须消费配对右括号内的完整值。至少覆盖：

| 类别 | 必须识别的标签或形式 | 代表输入 |
| --- | --- | --- |
| 中文会议编号 | `会议号码`、`会议号`、`会议码`，允许词内空格 | `会议 号：123 456 789` |
| 中文入会凭证 | `会议密码`、`入会码`、`入会密码`、`密码`、`口令` | `入会码：火炬`、`入会码（火炬）`、`密码 秘密口令` |
| 英文会议编号 | `meeting id`、`meeting number`、`meeting code` | `Meeting ID: 123-456-789` |
| 英文入会凭证 | `passcode`、`password`、`pwd`、`pin` | `PWD=omega`、`passcode a-b_C` |
| 平台加编号 | `腾讯会议`、`Zoom`、`Teams`、`飞书会议` 后的分段数字 | `腾讯会议 123 456 789` |
| URL | 任意位置的 `http://`、`https://`、`www.` | `入口：https://meet.example/join?pwd=x` |

凭证值至少支持：Unicode 中文/英文/数字、下划线、连字符，以及由空格或连字符分段的完整数字编号。匹配到带标签凭证后必须消费并替换完整值，不能只隐藏第一段；数字编号遇到后续普通文字时应终止，避免吞掉下一行介绍。URL 必须先作为整体隐藏，不能把查询参数拆成可见文本；合法 URL 路径或查询中的成对 `()`、`[]`、`{}` 必须连同内部内容完整隐藏，只有不配对的外层闭括号和句末标点可以留在占位符之后。

输出只使用稳定占位符 `[链接已隐藏]` 与 `[凭证已隐藏]`。相邻的同类敏感片段可以合并，但不得留下可重建原始凭证的前缀、后缀或数字分段。

### FR-PRIVACY-002 False-positive 边界

以下普通内容必须原样保留，不得因为包含平台名或相似词而隐藏：

- `密码学读书会`、`密码学基础`
- `3号会议室`
- `腾讯会议室 A`
- `Zoom 产品设计`、`Teams 协作复盘`、`飞书会议体验`
- `会议号码为什么总是很长？`
- `口令设计原则`、`密码管理实践`

无标签的普通数字、日期、时长和房间号不视为凭证。新增语法时必须同时补充对应正例和 false-positive，不能靠不断扩大无边界关键词列表实现。

### FR-PRIVACY-003 全字段与文件名防线

- `title`、`summary`、`presenter`、每一个 `tag` 和 `room` 在进入 `PosterModel` 前都经过同一纯函数脱敏。
- 按 SPEC-019，`PosterModel` 还包含公开 Topic ID 和可选的同日场次上下文；文件名加入北京时间时分和 ID，仍必须通过本规格的所有凭证脱敏和布局预算。
- `meetingUrl` 永远不进入 `PosterModel`；`hasMeetingUrl` 只生成不含原始入口的线上参与提示。
- 即使传入未经公开 API 映射的历史原始 `room`，模型层仍必须独立隐藏 URL、会议编号和密码；不能只依赖服务端公开响应。
- 文件名生成函数必须自行对标题脱敏，再执行非法字符清理和长度限制，不能信任调用方已经清理。文件名不得出现 URL 主机、会议号残片、中文密码、`pwd` 或 `passcode` 值。
- Canvas 绘制层只接受已脱敏的 `PosterModel`。自动化必须检查所有 `fillText`/换行输入，确保没有绕过模型的原始 Topic 字段。

## 4. 极限 Canvas 布局

### FR-LAYOUT-001 共享纵向预算

- 画布保持 1080×1440，左右安全区保持一致；标题、简介、信息卡、标签区和页脚必须由同一布局计划计算，不得一部分动态下移、另一部分使用会与其相撞的固定坐标。
- 布局计划必须为每个区域提供明确边界，满足：`title.bottom < summary.top < info.top < tags.top < footer.top`；相邻区域保留不少于 20px 的视觉间距。
- 页脚品牌标语、详情提示和站点来源使用保留区，不得被动态内容侵入。所有绘制边界均须位于画布安全区内。
- 80 字标题允许在 76px 至 48px 间自适应，并可在预算不足时安全省略；简介最多三行并安全省略。省略号自身也必须计入宽度。
- 30 字分享人与时长必须使用互不相交的槽位；分享人超出槽位时换行或省略，不得覆盖时长。

### FR-LAYOUT-002 五标签完整呈现

- 服务端允许的五个标签必须在海报中各出现一次，渲染器不得因剩余横向空间不足而 `break` 或静默丢弃。
- 标签区可采用等分列、换行或自适应字号，但必须预先纳入纵向预算。五个各 20 字的合法标签也必须全部保留一个可辨识的省略文本。
- 每个标签文本按胶囊内部可用宽度独立省略，不能只限制胶囊宽度后继续绘制完整字符串。
- 标签文字不得越出自身胶囊，不得与相邻标签、信息卡或页脚重叠；相同标签仍按输入顺序稳定绘制。

建议把换行、标签布局和各区域矩形提炼为不依赖 DOM 的纯布局结果，以便使用确定性字体测量夹具验证；具体算法不作为本规格约束。

## 5. 点击时读取最新 Topic

### FR-FRESH-001 最新快照生成

1. 用户点击卡片“生成海报”后立即打开带生成状态的弹窗，并调用公开的 `GET /api/topics/:id`。
2. 只能使用该次成功响应构建 `PosterModel`；列表中的 Topic 仅用于入口和加载占位，不得作为读取失败时的降级海报数据。
3. 最新 Topic 仍为未来的 `SCHEDULED` 且信息完整时，使用它的标题、排期、分享人、地点、标签和 revision 生成预览。另一协作者在点击前改期时，海报必须显示新时间而非旧列表时间。
4. 最新 Topic 已取消排期、归档、过期或缺少必要字段时，不生成旧海报；弹窗显示明确原因，刷新议题列表与统计，让陈旧入口消失或更新，并提供关闭/返回议题的操作。
5. Topic 已删除时显示“议题已被删除，无法生成海报”并同步列表。网络或服务错误保留弹窗并提供“重新获取”；重试必须重新发起 GET，不能复用失败前的快照。
6. 读取最新 Topic 是公开只读操作，不应触发协作口令弹窗。读取期间、失败后重试期间和 PNG 编码期间按钮必须有确定状态，不能重复生成或留下无响应按钮。

“最新”定义为生成动作触发后该次 GET 返回的原子 Topic 快照；本轮不引入持续实时订阅，也不保证响应返回后的远端变化自动重绘。

## 6. 跨端验收矩阵

### 6.1 模型与布局自动化

1. 对 FR-PRIVACY-001 的每个语法变体逐项测试，并在值中覆盖中文、英文、混合字符、分段数字、空格、连字符和换行；输出不得包含任一完整或残余 secret。
2. 相同 secret 分别放入 `title`、`summary`、`presenter`、五个 `tags` 和原始历史 `room`；序列化 `PosterModel`、文件名及所有绘制文本均不得包含 secret。
3. FR-PRIVACY-002 全部 false-positive 原样保留；历史公开 `room`/`meetingUrl` 隔离测试继续通过。
4. 使用 1–80 字中文标题逐长度穷举，并组合三行以上简介、30 字分享人及五个 20 字标签生成布局计划；逐项断言区域顺序、最小间距、画布边界和文本宽度，至少固定 44、45、55、56、60、61、80 字回归点，防止中等长度以较大字号五行时反而越界。
5. 五个标签均有且只有一个绘制项；每个文字宽度不超过胶囊内部宽度，不存在矩形相交。长中英文词、emoji 和无 `Intl.Segmenter` 回退继续安全省略。

### 6.2 API 与陈旧快照

1. 历史数据库中的混合 URL、纯中文/英文凭证和普通地点经公开单项 GET 仍分别映射为安全线上提示、隐藏提示和原地点；真实 `meetingUrl` 只由受保护入口返回。
2. 页面载入旧排期后，由另一客户端改期；点击“生成海报”必须先发起单项 GET，预览与下载使用新排期。
3. 页面载入后分别由另一客户端取消排期、归档和删除；点击旧入口不得生成旧 PNG，必须给出对应反馈并同步列表。
4. 单项 GET 首次失败、随后恢复；用户点击“重新获取”后成功生成，期间只保留一个弹窗和一个有效生成任务。

### 6.3 桌面 Chrome 与 Pixel 7

两端使用同一组包含以下内容的未来议题完成真实浏览器验收：

- 80 字标题；
- 足以占满三行的简介；
- 30 字分享人；
- 五个各 20 字标签；
- `入会码：火炬`、`会议号 123 456 789`、`pwd=omega` 和独立会议 URL 分布在不同可绘制字段。

验收要求：

- 单击一次进入加载、预览；不会请求外部图片或生成服务。
- 预览为 Blob 图片，有准确替代文本，自然尺寸与下载 PNG IHDR 均为 1080×1440。
- 浏览器记录的全部 Canvas 文本不含 `火炬`、`123`/`456`/`789` 段、`omega`、会议 URL 主机或其他夹具 secret；文件名同样不含。
- 五个标签在 Canvas 中全部绘制且不重叠；标题、三行简介、信息卡、标签和页脚区域不相交。
- “下载 PNG”可用，失败后可重试，关闭后 Blob URL 被释放且焦点回到“生成海报”。支持文件分享时继续提供分享；用户取消分享不显示错误。
- Pixel 7 弹窗和预览不产生页面级横向滚动，所有操作按钮高度至少 44px；单列布局提示使用“上方图片”或不依赖方向的措辞，不能声称图片在左侧。

## 7. 非目标

- 不把海报上传到服务端，不接入外部图片、二维码或生成式服务。
- 不在 PNG 中加入真实会议入口，即使查看者已经解锁协作。
- 不新增实时订阅、海报历史版本、模板编辑器或服务端图片缓存。
- 本规格不解决活动开始/结束时间状态机，也不解决叠层口令弹窗的 Esc 所有权；两项继续由 SPEC-003 后续轮次跟踪。

## 8. 完成条件

- 本规格全部隐私、布局、最新快照和跨端验收通过。
- SPEC-004 FR-POSTER-001 的既有资格、北京时间、Blob 生命周期、下载/分享、失败重试和焦点恢复回归通过。
- 全部 API/单元/E2E、TypeScript、生产构建和漏洞审计通过。
- 验证证据、实现提交和部署结果回写 `specs/iterations.md` 后，状态才可从 `Ready` 改为 `Accepted`。
