# SPEC-024：页面业务承诺、筛选空态与恢复入口一致性

- 状态：`Accepted`
- 创建：2026-09-02
- 优先级：P2
- 关联：SPEC-004、SPEC-011、SPEC-015、SPEC-019

## 1. 已复现偏差

1. Pixel 7 的结果摘要“清除条件”按钮为 68×34px，低于既定 44px 触控基线。
2. 本周真实存在活动时，搜索无匹配结果会让周历错误显示“本周还没有围炉活动”，按钮跳去“查看待认领议题”，把筛选结果误报为业务事实。
3. 纯线下活动没有会议入口，但列表 LIVE 文案和活动详情仍承诺“加入线上会议”；当日日程的泛化说明也把入会说成所有活动都有的能力。
4. 报名层称姓名是“公开署名”，实际匿名读取只返回人数，姓名仅向持有效协作会话的人展示。
5. `ENDED / ARCHIVED` 参与名单已经只读，却仍固定承诺“协作者可代为取消报名”；0 人时还邀请“成为第一位围炉伙伴”，而阶段规则已经禁止报名与取消。
6. 同日全部为 `ARCHIVED` 的完整议程仍固定承诺“报名、加入会议、生成海报”，但详情只允许查看历史参与、沉淀资料和维护/撤销。
7. 已解锁协作者从未来线上活动点击“加入会议”时，若会议入口首次读取遭遇临时网络错误或 `5xx`，弹窗只显示错误文字和关闭按钮；页面没有原地重试，用户必须猜测关闭后重新打开这一隐式绕行。
8. 会议入口请求已经从服务端取得 `200`、但浏览器尚未交付时，另一协作者可以取消排期；旧响应放行后，页面会首次写入已经失效的完整会议地址。组件只用卸载标记防关闭后的迟到响应，没有把敏感响应绑定到 Topic revision，也没有在展示前复核权威状态。
9. 上述权威复核只落在“进入线上围炉”弹窗，首次打开“编辑议题”和编辑 `412` 冲突恢复仍直接把 `meeting-access` 的地址注入表单。外部取消排期后放行旧 `200`，编辑框与页面 DOM 仍出现已失效凭证，且可能被误保存回议题。
10. 列表搜索无结果后的主空态“清除搜索”只执行 `setSearch('')`；按钮随空态卸载后，360/390/768/1440 四档等待 1.2 秒焦点均落到 `BODY`。结果已恢复但键盘与读屏用户失去议题区上下文，和顶部“清除条件”的稳定落点不一致。
11. 周历当前无活动时，“查看下一场”只更新周游标；远期周和活动正确出现，但原空态按钮卸载后焦点也落到 `BODY`，用户不知道跳转结果位于何处。
12. 初始议题列表 GET 失败后，“重新连接”只调用 `load()`；第二次读取成功并恢复卡片时，加载/错误空态整体卸载，390px 等待 1.2 秒焦点仍落到 `BODY`。
13. “查看下一场”修复后目标周事件已成为 `activeElement`，但通用 `scrollIntoView({block:'start'})` 把事件顶边放在约 0px；四档视口均被 65–77px 吸顶导航遮住，状态、时间和焦点轮廓不可见。

## 2. 业务规则

- 任何页面文案只能承诺当前数据和权限下真实存在的动作。`hasMeetingUrl=false` 时，不出现“可加入线上会议”的确定性描述；可用条件说明为“若提供线上入口”。
- 完整当日议程的介绍根据本页有序活动的实际能力组合：始终可承诺查看详情；只有 `UPCOMING / LIVE` 才说明报名，且只在确有线上入口时说明入会；只有无重叠的 `UPCOMING` 才说明海报。全部结束/归档时改为历史回顾语义。
- 报名隐私文案必须明确：姓名仅向已解锁协作者展示，当前不绑定个人账号，协作者可代为取消；不能称为公开信息。
- 参与名单文案必须服从当前阶段：`UPCOMING / LIVE` 可说明协作者代为取消并在空态邀请报名；`ENDED / ARCHIVED` 只陈述历史名单只读，0 人时显示“本期暂无参与记录”，不承诺已禁止的动作。
- 周历区分“当前自然周确实无活动”和“搜索/状态/阶段条件下无匹配”：后者显示当前条件无结果，并提供“清除条件”恢复；不得跳去无关待认领流程。
- 清除条件同时恢复 `ALL`、搜索和阶段过滤，保留当前视图与周游标；结果区和周历空态复用同一命令。
- 所有高频恢复按钮最小 44×44px，极端文字不造成横向溢出。
- 会议入口读取失败必须留在同一弹窗并提供“重新读取会议入口”动作；点击才清除旧错误并发起恰好一次新 GET，禁止自动重试或自动打开外部链接。失败反馈与重试动作必须可聚焦，成功后焦点转到“进入线上会议”；关闭弹窗仍回到原议题的“加入会议”触发器。
- `401` 仍进入既有解锁叠层，活动阶段变化产生的 `409` 仍关闭失效入口并同步业务反馈；弹窗关闭或阶段失效后的迟到成功响应不得重新暴露会议地址。
- 会议入口成功响应必须携带读取时的 Topic revision。客户端收到敏感值后、写入 DOM 前，必须精确读取当前公开 Topic，并同时满足：ID 相同、revision 相同、状态仍为 `SCHEDULED`、`hasMeetingUrl=true`、客户端阶段仍为 `UPCOMING / LIVE`。任一条件不满足即丢弃地址、关闭失效入口并同步最新状态；权威复核读取失败时也不得先显示地址，只能保留原地显式重读。
- 请求代次必须贯穿“敏感读取 + 权威复核”整个链条；关闭、退出协作、显式重试或阶段变化后，旧链条的任意迟到结果均无权改变界面。
- 会议弹窗、首次编辑和编辑 `412` 恢复必须复用同一个受验证敏感读取流程，禁止各自直接消费 `meeting-access`。失效结果只允许使用公开权威 Topic：不得把旧地址放入 input 的 value/defaultValue/attribute、React state、可见正文或序列化 DOM，也不得在后续提交中带回。
- 任何会卸载自身的筛选/搜索恢复按钮都必须在结果重新渲染后安排稳定焦点。主空态“清除搜索”只清关键词、保留当前状态/视图，并聚焦议题区标题（或仍存在的搜索框）；等待至少 1 秒不得落到 `BODY`。顶部结果摘要和周历空态继续按既有“清除全部条件”语义执行。
- 周历空态“查看下一场”在更新游标后优先聚焦目标 Topic 的周事件主按钮；若目标因并发变化不再存在，则聚焦周历标题。动态目标声明不小于 96px 的顶部滚动边距，并在聚焦后按真实吸顶导航高度复核可见区域；实现须在 8px 验收线之外保留至少 2px 亚像素取整余量，避免浏览器滚动时序或设备像素换算把焦点重新压到导航下。不得改变状态/搜索/阶段条件，不得自动打开详情。
- 初始加载错误的“重新连接”成功后聚焦议题区标题；若仍失败则保留错误空态并把焦点返回重试按钮/错误反馈。重试只发起一次读取，不改变筛选、排序或视图，也不重放业务写入。
- 所有动态业务落点不仅要拥有 DOM 焦点，还必须完整位于吸顶导航下的可视安全区。周事件目标在布局稳定后顶部至少为 header bottom + 8px；校正不得改变当前周、重新打开活动或产生平滑滚动二次漂移。

## 3. 验收标准

1. Pixel 7 对无结果搜索显示“当前条件下，本周没有匹配活动”，点击 44px 以上“清除条件”后恢复真实活动，停留周历。
2. 真实空周仍显示“本周还没有围炉活动”，下一场/待认领 CTA 语义不变。
3. 纯线下 UPCOMING/LIVE 卡片和详情不出现“加入会议/加入线上会议”承诺，也不渲染入口；线上活动仍显示入口与对应说明。
4. 当日议程说明按实际阶段与入口生成：4 场全归档议程仅承诺回顾，混合议程只描述至少一场真实存在的能力；报名弹窗在匿名/已解锁边界上文案一致；结束/归档名单的介绍、空态和按钮均为只读语义。
5. 全量类型检查、生产构建和桌面/Pixel E2E 通过。
6. 首次会议入口 GET 返回 `503` 时不自动发第二次请求，弹窗显示至少 44px 的“重新读取会议入口”；显式点击后只发一次新 GET，第二次 `200` 后展示正确 `href` 并聚焦“进入线上会议”。
7. 会议入口重试不得回退既有安全边界：`401` 解锁、阶段 `409`、关闭后的迟到 `200`、触发器回焦和会议地址非公开列表均通过回归。
8. 延迟会议入口 `200`，在交付前由另一协作者取消排期或推进到归档，再放行旧响应：页面正文、链接属性和 DOM 均不得出现旧地址，并同步为最新 Topic 状态；相同 revision 的正常响应在权威复核后仍一步显示。
9. 会议入口响应缺失或携带非法 revision 元数据时失败关闭且不显示地址；API 单元测试验证 `ETag` 与同一事务读取的 Topic revision 一致。
10. 首次编辑和编辑 `412` 恢复分别覆盖：延迟会议 `200` 后外部取消排期、移除链接或删除，随后放行；每条路径必须执行权威精确读取，表单值、属性与 DOM 均不含旧 secret，且不能发起携带旧地址的写入。复核 `503`、非法 ETag 和退出协作同样失败关闭。
11. 360/390/768/1440 搜索无结果后点击主空态“清除搜索”，议题结果恢复且原状态/视图保持；等待 1.2 秒焦点位于议题区标题或搜索框，不是 `BODY`，页面无横向溢出。
12. 当前空周存在远期下一场时，点击“查看下一场”后周标题和事件正确显示跨年信息；桌面与移动等待 1.2 秒焦点位于该 Topic 的周事件主按钮，若事件并发消失则位于周历标题，不落 `BODY`，且没有自动打开弹窗。
13. 初始 topics GET `503` 后点击“重新连接”，第二次 `200` 恢复卡片；360/390/768/1440 等待 1.2 秒焦点位于 `#topics h2`，请求数只增加一次且没有 mutation。若第二次仍失败，重试入口继续可聚焦操作。
14. 360/390/768/1440 点击空周“查看下一场”，等待 1.2 秒后目标 `.week-event-main` 仍为焦点，且 `target.getBoundingClientRect().top >= header.getBoundingClientRect().bottom + 8`；周标题与目标活动不变、页面无横溢。

## 4. 回归证据

2026-09-02 定向生产构建 E2E：桌面 Chromium 与 Pixel 7 的 4 场全归档议程仅显示回顾语义，不出现报名、入会或海报承诺；10 场未来联场继续按真实能力显示报名与海报，且没有线上入口时不出现入会承诺。与既有筛选空态、线下阶段、历史名单回归共同通过。

终验：360/390/768/1440 的“查看下一场”在 1.5 秒后均保持目标事件焦点，真实吸顶安全间距为 9.609–10.109px；清搜索、重新连接成功/失败和会议入口恢复均保持可见业务落点。最终完整 E2E 152 通过、8 项按职责跳过、0 失败/重试。
